## 2. 기본 계산

### `A09-UI-01` 계산 전→계산 완료

1. `업무 > 수주·작업`에서 `SCREEN-PRICE` 거래처로 새 수주를 만든다.
2. `SCREEN-FOLD-L` 절곡 작업을 추가한다.
3. 하단 `계산·가격`의 상태가 `계산 전`인지 확인한다.
4. `수주 계산`을 누른다.
5. 완료 팝업을 닫고 작업별 표와 주문 합계를 확인한다.

기본 seed 기대값:

| 항목 | 기대값 |
|---|---:|
| 개당 면적 | `0.2136㎡` |
| 개당 절곡 | `1회` |
| 개당 V-CUT | `0m` |
| 재질비 | `7,262원` |
| 절곡비 | `1,600원` |
| 할증 | `160원` |
| 공급가액 | `9,022원` |
| VAT 10% | `902원` |
| 총액 | `9,924원` |

- 상태가 `계산 완료`, 버전이 `1`이어야 한다.
- 가격 출처는 `거래처 전용`이어야 한다.
- 입력·결과 checksum 앞 12자와 계산 시각이 표시되어야 한다.

### `A09-UI-02` 여러 작업 합계

1. 작업 1을 복사해 작업 2를 만든다.
2. 계산 상태가 `재계산 필요`로 바뀌는지 확인한다.
3. `다시 계산`을 누른다.

기대 결과: 두 작업 행이 표시되고 공급가·VAT·총액이 작업 두 건의 합으로 계산된다. 새 계산 버전이 생성되며 이전 버전은 DB 이력으로 유지된다.

## 3. 입력 변경과 불변성

### `A09-STALE-01` 입력 변경 후 재계산

1. 계산 완료 상태에서 작업 수량을 `3`으로 바꾸고 저장한다.
2. 기존 합계가 즉시 덮어써지지 않고 `재계산 필요` 안내가 나타나는지 확인한다.
3. `다시 계산`을 누른다.

수량 3 단일 작업 기대값:

| 항목 | 기대값 |
|---|---:|
| 공급가액 | `13,534원` |
| VAT | `1,353원` |
| 총액 | `14,887원` |

기대 결과: 계산 버전이 1 증가하고 새로운 입력·결과 checksum이 저장된다. 작업 순서만 위·아래로 바꾸는 경우에는 가격 입력이 바뀌지 않았으므로 재계산 필요 상태가 새로 생기지 않아야 한다.

### `A09-IMMUTABLE-01` 가격표 변경

1. 계산 버전·총액·결과 checksum과 가격 출처를 기록한다.
2. `가격 관리`에서 해당 범위의 새 가격표 개정을 만들어 단가를 변경하고 검토·게시한다.
3. 기존 수주를 다시 연다.

기대 결과: 기존 계산 버전의 금액·trace·checksum은 그대로이며 자동으로 최신 단가를 결합하지 않는다. `다시 계산`을 실행했을 때만 새 가격표 개정 trace를 가진 다음 버전이 만들어진다.

## 4. 오류·상태·동시성

### `A09-ERROR-01` 가격 누락

적용 가격 행이 없는 테스트 재질로 작업을 만든 뒤 계산한다.

기대 결과: `적용할 가격 행이 없습니다` 계열의 오류 팝업이 나오며 일부 작업이나 0원 snapshot을 저장하지 않는다.

### `A09-CONFLICT-01` 두 탭 계산

1. 같은 수주를 두 탭에서 연다.
2. 첫 탭에서 계산한다.
3. 두 번째 탭에서 이전 lock으로 계산한다.

기대 결과: 늦은 요청은 `409` 충돌로 거부되고 최신 내용을 다시 불러온다. 같은 번호의 계산 버전이 중복되지 않는다.

### `A09-STATE-01` 취소와 권한

- 취소 수주는 기존 계산 결과를 읽을 수 있지만 계산·재계산 버튼은 없어야 한다.
- `order.read`만 있는 사용자는 결과를 읽지만 계산할 수 없어야 한다.
- 다른 조직의 주문·작업·가격 UUID는 접근할 수 없어야 한다.

### `A09-RWD-01`

브라우저 폭 `390px`, `768px`, `1280px`, `1920px`에서 확인한다.

- 전체 viewport 가로 스크롤이 없어야 한다.
