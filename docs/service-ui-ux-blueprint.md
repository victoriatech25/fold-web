## 1. 전환 목표

FOLD WEB은 더 이상 도면 편집기 프로토타입을 첫 화면으로 제공하지 않는다. 로그인 후 사용자는 조직의 업무 홈에서 현재 가능한 업무와 후속 업무를 구분해 보고, 필요한 화면으로 이동한다.

- 도면 편집기는 서비스의 핵심 도구이지만 서비스 전체가 아니다.
- 수주, 설계, 계산, 생산, 출력, 기준정보를 하나의 업무 체계로 연결한다.
- 실제로 구현된 기능만 동작 가능한 메뉴와 통계로 표현한다.
- 후속 기능은 `준비 중`으로 명시하고 가짜 데이터나 동작하는 것처럼 보이는 UI를 만들지 않는다.
- MFC의 업무 순서는 참고하되 창·버튼 밀집 구조와 실행 메커니즘은 계승하지 않는다.


## 3. 정보구조

내비게이션은 `모듈 → 화면` 두 단계다. 상단에 업무 모듈 탭을 두고, 선택한 모듈의 화면만 그 아래 서브탭과 왼쪽 메뉴에 나온다. 한 화면에서 볼 메뉴 수를 줄여 목록이 길어지지 않게 한다.

| 모듈 | 화면 | 현재 상태 | 경로 |
|---|---|---|---|
| 업무 홈 | 최근 작업, 빠른 시작, 실제 데이터 현황 | 구현 | `/` |
| 영업관리 | 수주 등록/조회 | 구현 | `/orders` |
| | 견적 관리, 출하 요청 | 준비 중 | 경로 미개방 |
| 설계·도면 | 도면 설계 | 구현 | `/fold-editor` |
| | 템플릿 | 구현 | `/fold-library` |
| 생산·출력 | 작업 큐 | 구현 | `/jobs` |
| | 생산·절단, 출력·이력 | 준비 중 | 경로 미개방 |
| 기준정보 | 거래처·현장 | 구현 | `/customers` |
| | 재질·두께 | 구현 | `/materials` |
| | 가격 관리 | 구현 | `/pricing` |
| | 회사·사업장 | 구현 | `/admin/company` |
| 시스템 | 조직 관리, 부서, 역할과 권한 | 구현 | `/admin/users`, `/admin/departments`, `/admin/roles` |
| | 감사 로그 | 구현 | `/admin/audit-logs` |

정의는 `src/components/app-shell/navigation-model.ts` 한 곳에 둔다. 상단 모듈 탭, 서브탭, 왼쪽 메뉴, 모바일 오버레이가 모두 이 정의를 읽으므로 화면을 추가할 때 고칠 자리가 하나다.

메뉴는 서버가 부여한 permission에 따라 노출한다. 권한이 없어 화면이 하나도 남지 않는 모듈은 탭 자체를 감춘다. 주소 직접 접근도 서버에서 다시 검증한다.

## 4. 화면 유형

### 4.1 업무형 화면

업무 홈, 영업, 기준정보, 관리 화면에는 공통 서비스 셸을 적용한다.

- 데스크톱: 상단 모듈 탭 + 모듈 화면 서브탭 + 왼쪽 모듈 메뉴 + 본문
- 모바일·태블릿: 상단 메뉴 버튼 + 오버레이 내비게이션 + 단일 열 본문. 오버레이에는 모든 모듈의 화면을 모아 보여 한 번에 찾게 한다.
- 조직명과 사용자명은 항상 확인 가능하되 본문을 방해하지 않는다.
- 현재 모듈과 현재 화면은 색상, 밑줄, `aria-current`로 동시에 표현한다.
- 화면이 스스로 제목을 그리는 경우 셸은 제목을 겹쳐 그리지 않는다.

### 4.2 집중 작업 화면

도면 설계는 캔버스 공간이 중요한 전문 작업 화면이므로 넓은 작업 영역을 유지한다.

- 별도 `/fold-editor` 경로를 사용한다.
- 상단에 업무 홈 복귀, 템플릿, 사용자 문맥만 둔다.
- 서비스 왼쪽 메뉴가 캔버스 폭을 상시 차지하지 않는다.
- 기존 반응형 도면·속성 패널 배치를 유지한다.

### 4.3 단계형 수주 화면 — 후속 기준

수주는 `기본정보 → 품목/설계 → 계산/금액 → 검토/승인 → 생산 요청` 단계로 구성한다. 긴 MFC 입력 화면을 그대로 재현하지 않고 다음 원칙을 적용한다.

- 목록과 상세 경로를 분리한다.
- 현재 상태에서 가능한 주 행동은 한 개를 우선 강조한다.
- 저장 상태, 승인 상태, 생산 상태를 같은 언어와 배지 규칙으로 표시한다.
- 계산 결과는 입력 근처의 요약과 전체 검토 화면에서 모두 확인할 수 있게 한다.
- 승인 이후 데이터는 직접 수정하지 않고 새 개정 또는 복사 흐름을 제공한다.

### 4.4 목록·상세 공통 패턴

기준정보와 업무 화면은 모두 같은 배치를 쓴다. 화면마다 조건과 버튼 자리가 달라지면 사용자가 매번 다시 찾아야 한다.

**목록 화면**

- 제목 줄 오른쪽에 등록 버튼 하나를 둔다. 등록은 본문에 펼치지 않고 팝업에서 받는다.
- 그 아래 조회조건 바(`QueryBar`)를 한 줄로 두고 `조회`·`초기화` 버튼을 오른쪽 끝에 고정한다.
- 상태처럼 값이 몇 개로 정해진 조건은 토글 chip 으로 두어 복수 선택을 그대로 보이게 한다.
- 결과는 표로 보여 한 행에서 핵심 항목을 가로로 비교한다. 좁은 화면에서는 표만 가로로 스크롤하고 문서 자체는 넘치지 않는다.

**상세 화면**

- 기능을 세로로 나열하지 않는다. 공통 탭(`Tabs`)으로 나눈다.
- 수주 상세는 `기본정보 · 절곡 작업 · 계산·금액 · 승인·생산 · 이력` 다섯 탭이다.
- 문맥(번호·상태·거래처·납기)과 주 행동(저장·복사·취소), 저장 상태는 탭 위 머리 영역에 고정해 탭을 바꿔도 자리가 같다.
- 선택되지 않은 탭도 DOM 에 남긴다. 탭을 오갈 때 입력 중이던 내용이 초기값으로 돌아가지 않게 한다.

## 5. 공통 UX 규칙

1. 한 화면의 제목과 목적을 상단에서 즉시 이해할 수 있어야 한다.
2. 주요 행동은 동사형 한국어로 표시한다. 예: `새 도면 설계`, `검토 요청`, `생산 요청`.
3. 파괴적 행동, 확인, 완료 알림은 승인된 공통 팝업을 사용한다. 필드 오류는 입력 가까이에 표시한다.
4. 빈 화면은 원인과 다음 행동을 함께 안내한다.
5. 로딩, 저장 중, 저장 완료, 충돌, 권한 없음 상태를 숨기지 않는다.
6. 색상만으로 상태를 전달하지 않고 텍스트·아이콘·접근성 속성을 함께 사용한다.
7. 390px 모바일부터 대형 데스크톱까지 가로 넘침 없이 동작해야 한다.
8. 터치 대상은 가능한 한 40px 이상을 유지한다.
9. 미구현 기능은 비활성 `준비 중` 상태로만 표시하며 실제 수치를 만들지 않는다.
10. 한국 국내 사용을 기준으로 날짜, 금액, 단위, 용어를 우선 설계한다.

## 6. 1차 구현 결과

- 로그인 후 `/`를 도면 편집기에서 업무 홈으로 변경했다.
- 공통 서비스 셸과 역할 기반 내비게이션을 만들었다.
- 실제 PostgreSQL의 초안, 게시 개정, 템플릿, 사업장 수만 업무 홈에 표시한다.
- 최근 초안을 `/fold-editor?draft=<id>`에서 바로 이어서 열 수 있다.
- 기존 편집기를 `/fold-editor`의 집중 작업 화면으로 이동했다.
- 템플릿과 관리 화면을 공통 서비스 셸에 통합했다.
- 모바일 메뉴, 본문 바로가기, 현재 메뉴 접근성 표기를 추가했다.
- 기존 초안 링크, 라이브러리 링크와 E2E 경로를 새 정보구조에 맞게 변경했다.
- 거래처 목록·상세, 담당자·고객 현장 관리 화면을 공통 서비스 셸과 권한 메뉴에 연결했다.
- 재질 목록·상세와 두께·계산 기준 상태 화면을 공통 서비스 셸과 권한 메뉴에 연결했다.

### 6.1 2026-08-22 정보구조 개편 (검수 완료)

세로로 긴 상세 화면과 12개가 한 줄로 늘어선 왼쪽 메뉴를 정리했다. 색상 계열은 기존 teal 그린을 그대로 쓴다. 사용자 화면 전체에 적용했다.

**공통 기반**

- 왼쪽 한 줄 메뉴를 `상단 모듈 탭 + 모듈 서브탭 + 왼쪽 모듈 메뉴` 3단으로 바꿨다.
- 메뉴 정의를 `navigation-model.ts` 한 곳으로 모았다.
- 공통 탭(`src/components/ui/tabs.tsx`)과 공통 조회조건 바(`src/components/ui/query-bar.tsx`)를 만들었다.
- 화면이 스스로 제목을 그리면 셸은 제목을 겹쳐 그리지 않는다.

**화면별 적용**

| 화면 | 적용 내용 |
|---|---|
| 수주 목록 | 조회조건 바, 상태 chip(복수 선택), 표 배치. 새 수주 등록을 팝업으로 |
| 수주 상세 | 다섯 섹션 세로 나열 → `기본정보·절곡 작업·계산·금액·승인·생산·이력` 다섯 탭 |
| 거래처 목록 | 조회조건 바와 표 배치 |
| 거래처 상세 | `기본정보·담당자·고객 현장` 세 탭 |
| 재질 목록 | 조회조건 바와 표 배치 |
| 재질 상세 | `기본정보·두께 항목` 두 탭 |
| 계산 기준 | 요약 카드는 고정, `개정 이력·처리 이력` 두 탭 |
| 가격 관리 | `가격표·가격등급·거래처 등급·가격 계산기` 네 탭, 가격표는 표 배치 |
| 조직 관리 | 사용자 초대 폼을 팝업으로 |
| 감사 로그 | 열 개 조회조건을 공통 조회조건 바로 |
| 작업 큐 | 다중 선택 상자를 상태 chip 으로 |
| 회사·사업장 | `회사 기본정보·사업장` 두 탭 |
| 템플릿 | 검색 폼을 공통 조회조건 바로 |
| 역할과 권한 | 영문 권한 키 나열을 한글 이름 chip 과 팝업으로. 권한 선택은 한글 분류별 묶음 |

같은 모듈 안에서는 상단 서브탭과 왼쪽 메뉴에 같은 링크가 두 번 나온다. 참조한 ERP 화면의 구조를 그대로 따른 결과이며 2026-08-22 검수에서 현재 구조를 유지하기로 했다. 자동 검증은 왼쪽 메뉴로 범위를 좁혀 구분한다.

## 7. 후속 적용 순서

1. `P2-A03` 재질·두께 화면을 실제 표본으로 사용자 검수한다.
2. `P2-A04` 이후 계산 규칙·원판·가격 화면은 같은 서비스 셸과 목록/상세 패턴을 재사용한다.
3. `P2-A07`에서 수주·작업 메뉴를 활성화하고 단계형 수주 화면을 구현한다.
4. 생산·출력 기능이 구현되는 시점에 준비 중 메뉴를 실제 권한·상태 기반 메뉴로 교체한다.
5. 실제 사용자 화면 검수에서 메뉴 용어, 정보 밀도, 작업 횟수를 기록하고 기준선을 보정한다.
6. 2026-08-22 전체 화면에 목록·상세 패턴 적용을 마쳤다. 이후 새로 만드는 화면은 이 패턴을 기본값으로 쓴다.

## 8. 검수 기준

- 로그인 후 업무 홈이 표시되고 도면 편집기가 자동으로 열리지 않는다.
- 구현 기능과 준비 중 기능이 명확히 구분된다.
- 최근 초안에서 해당 편집 화면으로 이동할 수 있다.
