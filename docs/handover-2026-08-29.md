## 2. 이번 세션에서 한 일

### 2.1 `P2-B05` 검수 전체 승인

[검수 가이드](./P2-B05-screen-test-guide.md)의 항목 2-1~2-8 을 사용자가 전체 승인했다.

**2-4 의 업무 판단이 이 작업의 열린 질문이었다.** "현장이 손보는 이유가 이 부품은 저 판에 같이 인가, 여기 이 자리에 인가." 전체 승인이므로 **고정 방식으로 충분**하다는 결론이고, `D2-B05-J` 를 (가) 고정 후 재실행으로 확정했다. **좌표 직접 편집은 넣지 않는 것으로 닫혔다.** 나중에 실제로 필요해지면 그때 다시 연다.

### 2.2 배치 그림 방향을 고쳤다 — `D2-B05-L`

검수 중에 나온 유일한 코드 수정이다. `src/components/cutting/cutting-plan-detail-panel.tsx` 한 파일이다.

**배치 그림은 긴 쪽을 가로로, 배치 원점을 좌상단으로 놓는다.**

| 원판 모양 | 그리는 방식 |
|---|---|
| 세로가 긴 원판 (1000×2000 등) | 시계 방향으로 90도 눕힌다 |
| 가로가 긴 원판 (2440×1220 등) | 그대로 두고 y 를 위에서 아래로 읽는다 |

`toScreen` 함수 하나로 좌표를 화면으로 옮긴다. 처음에는 그림 전체를 SVG `transform` 으로 돌리고 글자만 되돌렸는데, 원점이 좌상단으로 와야 해서 좌표 변환으로 바꿨다. 글자를 되돌리는 처리가 없어져 코드가 짧아졌다.

**계약(`cutting-contract-v1`)의 좌표는 그대로다.** 왼쪽 아래 원점·y 위쪽이고 solver 결과와 저장된 개정은 손대지 않았다. DXF 가 같은 규약을 쓰기 때문에 계약까지 뒤집으면 뒤집는 자리가 화면·DXF·도면 출력으로 늘어난다.

**세로가 긴 원판은 시계 방향 회전이라 좌우가 뒤집히지 않는다.** 반면 가로가 긴 원판은 회전 없이 y 만 뒤집어 읽으므로 실물을 위아래로 뒤집어 본 그림이 된다. 결(grain)은 방향만 있고 앞뒤 구분이 없어 재단에는 지장이 없다고 봤다. 나중에 도면·작업지시를 실물과 대조할 때 기억해 둘 것.

`G` 가 가장 크고 나머지 셋은 그만큼 크지 않다.

### 결정을 기다리는 동안 할 수 있는 것 — 기록 보정 3건

1. **`D2-B03-E` 회전 정책 값 불일치.** 기준정보는 `FREE | KEEP_GRAIN`, 계약은 `FREE | FIXED` 다. 문서가 "같은 값" 이라고 적은 것이 사실과 다르다. 코드는 맞다(입력 빌더가 옮긴다).
2. **`P0-03` 의 `sellplaninfo` 성격 오기.** "재단/DXF 관련 표본" 이 아니라 절곡 DXF 원문이다.
3. **브랜치 이름과 내용 불일치.** `p2-a09-a11-order-calculation-approval-history` 인데 실제로는 `P2-B01`~`B05` 가 들어 있다.

## 6. 이어받기

절차는 [2026-08-23 인계 5절](./handover-2026-08-23.md)과 같고 바뀐 것이 없다. 요약하면 터미널 셋이다.

```bash
docker compose up -d storage
```

```bash
npm run dev
```

```bash
npm run worker
```

- 웹은 `http://localhost:8000` 고정이다. `APP_ORIGIN` 과 맞아야 한다.
- **worker 는 코드를 바꾸면 반드시 다시 띄운다.** watch 가 없다.
- **스키마를 바꿨으면 `npm run db:migrate:deploy` 로 개발 DB 에도 올린다.** `fold_web_test` 만 올리고 `fold_web_dev` 를 빼먹으면 화면이 깨진다.
- 로그인은 [로컬 화면 테스트 계정](./local-screen-test-account.md).

`.claude/launch.json` 이 작업 트리에 생겼다. 브라우저 미리보기가 개발 서버를 띄우려고 만든 로컬 설정이라 커밋하지 않았다.
