## 2. 그룹재단 — 정의가 두 번 바뀌었다

가장 중요한 것부터. 웹 문서는 그룹재단을 "여러 수주를 묶어 한 판에 재단" 으로 적어 왔고, MFC 소스를 처음 읽었을 때는 "레이저 그룹 지정 + DXF" 로 결론냈다. **둘 다 틀렸다.** 사용자가 확인한 정의는 이렇다.

> 재단 결과를 한 화면에서 손으로 편집한다 — 원판별 부품 배치를 옮기고, 새 원판을 추가하고, 원판 사이로 이동한다. DXF 는 원판마다 하나씩, 화면에 배치된 모습 그대로 나간다. 레이저 그룹·절단선·필름은 그 안의 부속 기능이다.

이 정의로 [P2-B11](./work-items/P2-B11-group-cutting.md)을 전면 재작성했고, `P0-02`·`P2-B05`·`P2-B06` 의 잘못된 인용을 정정했다. 사용자 결정 `D2-B11-A~H` 가 모두 닫혀 있다. `D2-B05-J` 에서 뺐던 "(다) 좌표 직접 편집" 이 이 작업으로 열렸다.

### 만든 것

| 단계 | 내용 | 주요 파일 |
|---|---|---|
| B11-1 | 편집 개정(`source=MANUAL_EDIT`)·`annotations`·`warnings`, 검증(겹침·경계·수량 거부, guillotine·kerf 경고), `manual-revisions`·`validate` API | `domain/cutting/annotations.ts`·`manual-edit.ts`, `server/cutting/cutting-plan-service.ts` |
| B11-2 | `/cutting/[planId]/edit` 편집기 — 드래그 이동(원판 사이 포함)·스냅·회전·미배치 투입·원판 추가/삭제·실행취소·디바운스 검증·저장 | `domain/cutting/editor-state.ts`·`screen-transform.ts`, `components/cutting/cutting-plan-editor.tsx` |
| B11-3 | 도구 모드 — 레이저 그룹(사각형 선택으로 묶기, 격자·같은 부품만), 절단선, 필름. 상세 화면 표시 | 같은 파일 |
| B11-4 | 원판 DXF — MFC 레이어 규칙, 중복선 병합, 그룹 안쪽 `- -`, 절곡선, 필름, 그룹 파일, zip, 날짜 순번, `cutting.dxf` 큐 작업, 파일 목록 API·화면 | `domain/cutting/sheet-dxf.ts`, `server/cutting/cutting-dxf-service.ts`, `server/dxf/zip-writer.ts` |
| B11-5 | [검수 가이드](./P2-B11-screen-test-guide.md) | — |

E2E 는 이제 [`e2e/global-setup.ts`](../e2e/global-setup.ts) 가 재단 전용 worker(`WORKER_JOB_TYPES=cutting.optimize,cutting.dxf`)를 띄운다. 재단 결과가 있어야 편집기를 검증할 수 있어서다. `P2-B10` 생산 E2E 도 이 기반을 쓴다.

### 가정 위에 있는 것 — MFC 실제 DXF 로 닫는다

DXF 의 좌표 원점·회전, `{색상}` 문자열(지금은 재질 변형 `code`, 하이픈 포함), `-V-150` 이 1.5mm 인지, `-V1-` 의 용도, 원판 외곽에 trim 포함 여부, 중복선 옵션, 레이저 그룹 **경계선**의 처리, 그룹 파일의 레이어 규칙 — 열 가지가 [P2-B11 4.11](./work-items/P2-B11-group-cutting.md) 에 있다. **현장 PC 의 `export_dxf` 폴더에서 MFC 로 낸 원판 파일 + 그룹 파일 한 벌**(필름 on/off, V-cut 있는 것 섞어서)을 받아 가이드 2-8 로 대조한다. 레거시 DB 에는 없다.

## 3. 운영 배포 전에 확인할 것

이번 커밋을 태그로 배포하기 전에 반드시 본다. 순서대로.

| # | 확인 | 왜 |
|---|---|---|
| 1 | **운영 `.env` 의 `DATABASE_URL` 계정에 DDL 권한이 있는가** | `deploy.sh` 가 이제 `prisma migrate deploy` 를 먼저 돌린다(H1). 없으면 `.env` 에 `MIGRATION_DATABASE_URL` 을 넣는다 |
| 2 | **새 테이블 `CuttingDxfSequence` 에 앱 계정 GRANT** | 앱 계정과 마이그레이션 계정이 나뉜 구성이면 `migrate deploy` 뒤 `GRANT SELECT, INSERT, UPDATE, DELETE ON "CuttingDxfSequence" TO <앱 계정>;`. 없으면 DXF 생성이 `permission denied`. [배포 가이드](./deployment-guide.md) 참조. 1번이 "테이블 소유자 계정" 이면 필요 없다 |
| 3 | `.env` 에 `AUTH_TRUST_PROXY=true` | M2. 단 nginx 가 `proxy_set_header X-Forwarded-For $remote_addr;` 로 **덮어쓰는지** 먼저 확인. 이어 붙이는 설정이면 켜지 않는다 |
| 4 | 헬스체크가 DB 를 본다 | H4. `DATABASE_URL` 계정에 `_prisma_migrations` `SELECT` 권한이 있어야 200 이다. 배포 직후 `curl /api/health` 로 `applied === expected` 를 본다 |
| 5 | 이미지가 약 100MB 커졌다 | Prisma CLI 를 넣었다(H1). Docker 데이터 루트는 `/data` 라 여유는 있다 |
| 6 | 운영 저장소(MinIO) | 원판 DXF 는 `FileAsset` 으로 저장소에 보관한다. **운영에는 아직 저장소가 없다**(`P2-C08` 예정). 저장소가 없으면 파일 행은 `PENDING` 으로 남고 내려받기가 막힌다. 그룹재단을 운영에서 쓰려면 `P2-C08` 이 먼저다 |

- 통합·E2E 는 테스트 DB 를 `prisma migrate reset` 으로 초기화하는데 Prisma 가 AI 실행을 막는다. 사용자 동의 문장을 `PRISMA_USER_CONSENT_FOR_DANGEROUS_AI_ACTION` 에 넣어야 돈다

- MFC 소스 폴더(`~/Library/Mobile Documents/com~apple~CloudDocs/회사/hicomtech/도면`)는 이제 읽힌다. CP949 와 UTF-8 이 섞여 있어 `iconv` 가 실패하면 원본을 그대로 쓴다. 폴더 안에서 직접 grep 하면 매우 느리다 — 복사해서 읽는다
- 재단 편집기의 드래그는 실제 포인터 이벤트로 동작한다. 브라우저 자동화 도구 중 마우스 이벤트만 내는 것은 `pointerdown` 을 만들지 않아 움직이지 않는다. Playwright `page.mouse` 는 된다
