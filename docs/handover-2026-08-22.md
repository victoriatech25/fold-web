### 2.3 검수 중 실제로 잡힌 결함 둘

기록해 둘 가치가 있다. 둘 다 자동 검증이 못 잡고 사람이 화면에서 잡았다.

1. **`READY` 인데 바이트가 없는 파일** — 저장소 도입 전에 만들어진 `FileAsset` 행에 다운로드 URL을 발급해 사용자가 MinIO 의 `NoSuchKey` XML 을 그대로 봤다. 발급 전에 객체 존재를 확인하고 없으면 `PENDING` 으로 되돌리도록 고쳤다(`7dbfc75`).
2. **worker 가 옛 코드로 실행 중** — `npm run worker` 는 watch 가 없어 코드를 바꿔도 옛 모듈로 계속 돈다. 작업이 성공하면서도 새 동작을 하지 않아 원인을 찾기 어려웠다. 검수 가이드에 명시했다(`a1b7f97`).

## 3. 다음 작업 — `P2-B04` 신규 재단 solver

착수 조건은 모두 갖춰져 있다.

| 준비물 | 위치 |
|---|---|
| 중립 계약 | `src/domain/cutting/schema.ts` (`cutting-contract-v1`) |
| 검증 함수 | `src/domain/cutting/validate.ts` — 위반 코드 14가지 |
| 실제 입력 표본 | `src/domain/cutting/fixtures/legacy-input-samples.json` — 3건, 각 부품 12개 |
| 작업 queue | `P2-B01` 완료. `cutting.optimize` 종류를 추가하면 된다 |
| 상세계획 | [P2-B03 재단 계약](./work-items/P2-B03-cutting-contract.md) |

**합격 기준은 `validateCuttingResult` 위반 0건이다.** 원판 수·수율 비교는 기대값이 없어 켤 수 없다(아래 4-1).

표본에는 `3000×176`, `2900×496` 처럼 `1220×2440` 원판에 그대로 안 들어가는 부품이 섞여 있다. 회전하거나 더 큰 원판(`1220×3000`, `1220×4000`)을 골라야 하므로 solver 의 원판 선택 로직이 처음부터 필요하다.

### 5.2 걸리기 쉬운 것

- **worker 는 코드를 바꾸면 반드시 다시 띄운다.** watch 가 없다. 기동 로그의 `types` 로 새 코드인지 확인한다.
- **`prisma generate` 를 돌린 뒤에도 worker 를 다시 띄운다.** 옛 Prisma 클라이언트를 물고 있으면 새 컬럼에서 깨진다.
- **e2e 를 돌리기 전에 개발 서버를 내린다.** Next 는 같은 디렉터리에서 두 번째 dev 서버를 거부한다.
- **테스트 DB 초기화는 Prisma 가 AI 실행을 막는다.** 사용자 동의를 받아 `PRISMA_USER_CONSENT_FOR_DANGEROUS_AI_ACTION` 에 동의 문장을 그대로 넣어야 한다.

### 5.3 레거시 참조 DB

읽기 전용 조사용이다. 접속 문자열은 `.env.local` 의 `LEGACY_REFERENCE_DATABASE_URL` 에만 둔다. 문서·코드·fixture 에 적지 않는다(`P0-03`).
