# 회사 등록·관리 화면 테스트 가이드

> 대상: [플랫폼 관리자 — 회사(조직) 등록·관리](./work-items/platform-organizations.md)
>
> 작성일: 2026-09-13
>
> 계정: [로컬 화면 테스트 계정](./local-screen-test-account.md) — 플랫폼 관리자로 보장된다

## 준비

```bash
npm run db:migrate:deploy
npm run auth:ensure-local-screen-test-account
npm run dev
```

## 1. 메뉴 노출

| 단계 | 기대 |
|---|---|
| 1-1 | 로그인 후 상단 `시스템` 탭 → 좌측 메뉴 끝에 `회사 등록·관리` 가 보인다 |
| 1-2 | `npm run auth:set-platform-admin -- --email screen-test-admin@local.test --platform-admin false` 실행 후 새로고침 → 메뉴가 사라진다. 다른 `시스템` 메뉴(조직 관리 등)는 그대로다 |
| 1-3 | 그 상태로 `/admin/organizations` 를 주소창에 직접 입력 → 404 |
| 1-4 | `--platform-admin true` 로 되돌리고 새로고침 → 메뉴가 다시 보인다 |

## 2. 등록

| 단계 | 기대 |
|---|---|
| 2-1 | 코드 `demo-co`, 이름 `데모 절곡` 입력 → 등록 | 목록에 `DEMO-CO`(대문자) · 상태 `사용` · 사용자 0명 으로 나타난다 |
| 2-2 | 같은 코드로 다시 등록 | `이미 사용 중인 회사 코드입니다.` |
| 2-3 | 코드에 한글·공백 | 브라우저 pattern 에 걸려 제출되지 않는다 |
| 2-4 | `시스템 > 감사 로그` | `조직(회사) 등록` 항목이 남아 있다 |

## 3. 변경·정지

| 단계 | 기대 |
|---|---|
| 3-1 | `DEMO-CO` 이름을 바꾸고 저장 | 새 이름으로 갱신 |
| 3-2 | 상태를 `정지` 로 바꾸고 저장 | `회사 정지` 확인 팝업(소속 사용자 수 표시) → `정지` 누르면 목록 아래로 내려가고 상태 `정지` |
| 3-3 | `LOCAL_DEV`(내 회사) 행 | 상태 select 가 비활성이고 `내 회사` 표시 |
| 3-4 | 두 탭에서 같은 회사를 열고 한쪽에서 저장한 뒤 다른 쪽에서 저장 | `회사 정보가 변경되었습니다. 새로고침 후 다시 시도해 주세요.` |

## 4. 회사 관리자 발급

| 단계 | 기대 |
|---|---|
| 4-1 | `DEMO-CO` 를 `사용` 으로 되돌린 뒤 행 아래 `관리자 발급` | 이메일·이름 폼이 열린다 |
| 4-2 | 이메일 `demo-admin@example.test`, 이름 `데모 관리자` → 발급 | 노란 상자에 비밀번호 설정 주소가 한 번 표시되고, 관리자 목록에 `데모 관리자 · 초대` 가 나타난다 |
| 4-3 | 같은 이메일로 다시 발급 | `이미 등록된 이메일입니다.` |
| 4-4 | 시크릿 창에서 주소를 열어 비밀번호 설정 → 로그인 | 상단 조직명이 `데모 절곡`, `시스템 > 조직 관리` 가 보이고 `회사 등록·관리` 는 없다. `/admin/organizations` 직접 접근은 404 |
| 4-5 | 다시 플랫폼 관리자로 보면 | 관리자 상태가 `활성` 으로 바뀌어 있다 |
| 4-6 | 정지된 회사 행 | `관리자 발급` 버튼이 없다 |

## 정리

검수 뒤 `DEMO-CO` 는 개발 DB 에 남겨 두어도 된다(정지 상태라 로그인에 영향 없음). 지우려면 역할·사업장·프로필이 딸려 있으므로 SQL 로 조직 row 를 지운다(`CompanyProfile` 은 cascade, `BusinessSite`·`Role` 은 먼저 지운다).
