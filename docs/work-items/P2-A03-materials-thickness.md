## 1. 목표

조직별 재질과 해당 재질에서 실제 사용하는 두께를 서버 기준정보로 관리하고, 게시된 계산 기준을 도면 설계에서 안정적으로 선택할 수 있게 한다.

```text
재질 등록
→ 재질별 두께 등록
→ 계산 기준 게시 여부 확인
→ 도면 설계에서 게시 기준 선택
→ 도면 문서에 당시 값 불변 복사
```

이번 작업은 재질·두께의 식별과 수명주기를 완성한다. 연신율·컷 깊이·적용 각도의 작성·검토·게시 화면은 `P2-A04`에서 구현한다. 다만 현재 게시 개정이 두께의 가변 내부 반경을 실시간으로 읽는 문제는 이번 migration에서 해소해 기존 게시 기준의 불변성을 보장한다.

## 2. 현재 웹 기준선

현재 Prisma에는 다음 뼈대가 이미 있다.

- `Material`: 조직, 코드, 이름, 밀도, 활성 상태
- `MaterialVariant`: 재질별 코드·이름·두께·기본 내부 반경
- `MaterialRuleRevision`: FIX/RATIO, 연신율, 컷 깊이, 각도, 소수 처리, 상태와 유효기간
- 게시된 유효 개정만 `/api/v1/fold-material-options`에서 조회
- 새 초안·저장 문서는 게시 개정 값을 JSONB 문서의 재질 snapshot으로 복사
- seed에는 알루미늄 1T·2T·3T와 게시 개정이 존재

현재 보완점은 다음과 같다.

1. 재질·두께 관리 서비스·API·화면이 없다.
2. `Material`, `MaterialVariant`에 낙관적 잠금과 정렬 순서가 없다.
3. 게시 개정의 내부 절곡 반경이 `MaterialVariant.defaultInsideRadiusMm`을 실시간으로 읽어 게시 후 변경 가능하다.
4. 브라우저 `localStorage` 프리셋과 서버 게시 기준이 함께 존재해 실제 서비스의 기준정보 출처가 불명확하다.
5. 신규 두께를 등록해도 계산 기준을 게시하기 전에는 도면에서 사용할 수 없다는 상태 표시가 없다.

MFC는 재질과 두께를 독립 문자열 목록으로 관리하고 원자재 행에서 조합한다. 이름 변경 시 연관 품목 문자열을 직접 갱신하고 물리 삭제하는 방식은 서버 UUID 참조와 이력 보존에 맞지 않으므로 계승하지 않는다.

| 원본 | 집계 | 해석 |
|---|---:|---|
| `codetb` MATERIAL | 11개 | 재질 공통 목록 |
| `codetb` THICK | 10개 | 두께 공통 목록 |

| `rawcate` 중복 조합 | 3개 조합 | H/L 1.2T 3행, P/L 1.2T 3행, 티타늄골드 1.2T 2행; 계산 값은 조합 안에서 동일 |
| `rawcate.cutangle` | 전부 135° | 웹 기본값의 근거이지만 고정 규칙으로 간주하지 않음 |

## 5. 권장 데이터 계약

### 5.1 `Material`

| 필드 | 규칙 |
|---|---|
| `id` | UUID PK |
| `organizationId` | 모든 조회·변경의 조직 경계 |
| `code` | 조직별 고유, 영문 대문자·숫자·`-`·`_`, 생성 후 불변 |
| `name`, `normalizedName` | 한국어 표시명 필수, 조직 내 정규화 이름 중복 차단 |
| `densityKgPerM3` | 선택, 0보다 큰 kg/m³; 미확정은 `null` |
| `sortOrder` | 사용자 표시 순서, 같은 값이면 이름·ID 순 |
| `memo` | 내부 비고 선택 |
| `active`, `deletedAt` | 물리 삭제 없이 비활성·재활성 |
| `lockVersion` | 수정 충돌 방지 |

### 5.2 `MaterialVariant`

| 필드 | 규칙 |
|---|---|
| `materialId` | 소속 재질 필수 |
| `code` | 조직별 고유, 생성 후 불변. 예: `AL-2T` |
| `name` | 기본 표시명. 예: `알루미늄 2T` |
| `thicknessMm` | 0보다 큰 Decimal mm, 같은 재질 안에서 중복 차단, 생성 후 불변 |
| `defaultInsideRadiusMm` | 0 이상, 신규 계산 개정의 초기 제안값 |
| `sortOrder` | 기본은 두께 오름차순, 필요 시 사용자 순서 보정 |
| `active`, `deletedAt`, `lockVersion` | 비활성·충돌 방지 |

두께는 문자열 `1.2T`가 아니라 Decimal `1.2`로 저장하고 UI에서 `1.2T`로 표시한다. 재질과 두께 조합이 실제 사용 단위이며, 서로 다른 원판 규격은 별도 `SheetItem`이다.

### 5.3 게시 개정 불변 보완

`MaterialRuleRevision`에 `insideBendRadiusMm`을 추가한다. 기존 행은 당시 `MaterialVariant.defaultInsideRadiusMm`으로 채운다. 이후 게시 기준 조회와 도면 snapshot은 개정 행의 값을 읽는다.

```text
MaterialVariant.defaultInsideRadiusMm
  └─ 새 계산 기준 초안의 제안값

MaterialRuleRevision.insideBendRadiusMm
  └─ 해당 개정에서 고정된 불변 계산값
```

재질 밀도는 `P2-A05/P2-A09`에서 중량 계산 snapshot에 복사한다. 기존 도면 문서는 연신·형상 계산에 밀도를 사용하지 않으므로 이번 단계에서 문서 schema를 불필요하게 변경하지 않는다.

## 6. 상태와 업무 규칙

- 재질을 비활성화하면 하위 두께의 상태값은 바꾸지 않지만 신규 선택 결과에서는 함께 숨긴다.
- 두께를 비활성화해도 기존 도면·템플릿 snapshot은 그대로 열리고 계산된다.
- 재질 코드, 두께 코드와 두께 값은 참조 안정성을 위해 생성 후 변경하지 않는다.
- 재질명·두께 표시명·밀도·기본 반경은 수정 가능하나 기존 도면 snapshot을 바꾸지 않는다.
- 신규 두께는 계산 기준이 게시되기 전까지 `계산 기준 필요` 상태이며 도면 선택 목록에 나타나지 않는다.
- `P2-A04` 전에는 기존 seed 게시 기준만 계속 사용할 수 있고 새 규칙 값을 자동 생성하지 않는다.
- 비활성·재활성, 밀도·기본 반경 변경은 감사 로그에 before/after로 남긴다.

## 7. API와 화면 계약

### 7.1 Route Handler

```text
GET    /api/v1/materials
POST   /api/v1/materials
GET    /api/v1/materials/:materialId
PATCH  /api/v1/materials/:materialId

POST   /api/v1/materials/:materialId/variants
PATCH  /api/v1/materials/:materialId/variants/:variantId
```

목록은 검색어·비활성 포함·cursor를 지원한다. 상세 응답은 하위 두께와 각 두께의 현재 유효 게시 개정 요약을 포함한다. 모든 변경은 `Origin`, `expectedLockVersion`, 조직 경계와 표준 오류 envelope를 적용한다.

### 7.2 화면

- `/materials`: 재질 코드·이름 검색, 활성 상태, 밀도, 두께 수, 계산 기준 미게시 수
- `/materials/[id]`: 재질 기본정보와 두께 목록, 신규 두께, 활성 상태, 현재 게시 개정 읽기 요약
- 서비스 셸 `관리` 영역에 `재질·두께` 메뉴를 `material.read` 권한으로 표시
- `material.write`가 없으면 저장·상태변경 버튼을 숨기고 조회 전용으로 제공
- 성공·확인·충돌·비활성화는 공통 팝업, 필드 오류는 입력 가까이에 표시
- 데스크톱은 목록·카드 혼합, 모바일은 단일 열과 스크롤 가능한 상세 대화상자 사용

## 10. 테스트 기준

- 다른 조직의 재질·두께를 조회하거나 변경할 수 없다.
- 같은 조직에서 재질 코드·정규화 이름, 같은 재질에서 두께가 중복되지 않는다.
- Decimal은 number가 아닌 canonical 문자열로 API를 왕복하며 정밀도가 손실되지 않는다.
- 게시 개정의 내부 반경은 variant 기본값 변경 후에도 바뀌지 않는다.
- 비활성 재질·두께는 신규 도면 선택에서 제외되지만 기존 문서 snapshot은 정상 계산된다.
- 계산 기준 미게시 두께는 관리 화면에 분명히 표시되고 도면 선택에는 나타나지 않는다.
- stale 저장은 `409`, 권한 없는 변경은 `403`, 다른 조직 자료는 `404`로 처리한다.
- 모든 확인·완료 팝업은 공통 팝업이며 390px에서 가로 넘침이 없다.
- 기존 P1 계산 120건, 도면·템플릿·회사·거래처 E2E가 계속 통과한다.
