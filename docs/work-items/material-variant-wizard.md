# 두께 등록 마법사 — 재질·두께 등록 흐름 정리

> 상태: `VERIFYING` — 구현 완료(2026-09-13). [화면 테스트 가이드](../material-variant-wizard-screen-test-guide.md)로 사용자 검수 대기
>
> 계기: 2026-09-13 사용자 지적 — "재질·두께 등록 스텝이 직관적이지 않고, 페이지 이동이 많고, 어떻게 진행되는지 알기 힘들다"
>
> 관련: [P2-A03 재질·두께](./P2-A03-materials-thickness.md), [P2-A04 계산 규칙](./P2-A04-material-calculation-rules.md)

## 1. 문제

두께 하나를 설계에서 쓸 수 있게 만들기까지 **페이지 3개, 팝업 6개, 알림 5개**를 거쳤다.

| 단계 | 화면 | 동작 |
|---|---|---|
| 1 | 재질 목록 | `새 재질` 팝업 → 알림 → 재질 상세(기본정보 탭) |
| 2 | 재질 상세 | `두께 항목` 탭 → `두께 추가` 팝업 → 알림 |
| 3 | 재질 상세 | `계산 기준` → 계산 기준 페이지로 이동 |
| 4 | 계산 기준 | `새 개정 만들기` 팝업 → `초안 저장` → 알림 |
| 5 | 계산 기준 | `검토 요청` 팝업 → 알림 → `게시` 확인 → 알림 |

어느 화면에도 "지금 몇 번째 단계이고 다음에 무엇을 해야 하는지"가 없었다. `계산 기준 필요` 배지가 전부였다.

## 2. 결정

### 2.1 도메인은 그대로, 화면 흐름만 바꾼다

초안 → 검토 → 게시 구조와 `material.write` / `material.approve` 권한 분리는 유지한다(`P2-A04`). 바뀌는 것은 사용자가 그 단계를 **한 자리에서** 밟게 하는 것뿐이다.

### 2.2 두께 추가는 한 팝업의 3단계 마법사

`두께 추가` → `① 두께 정보 → ② 계산 기준 → ③ 확인·게시`. 상단에 진행 표시를 둔다.

- ①에서 `두께만 등록` 으로 빠져나올 수 있다(계산값을 아직 모를 때)
- ③ 마지막 버튼은 권한에 따라 다르다 — 승인 권한이 있으면 `등록하고 게시`(초안 저장 → 검토 요청 → 게시를 연달아 실행), 없으면 `등록하고 검토 요청`
- **승인 권한이 있으면 게시까지 자동으로 한다.** 사용자 결정(2026-09-13). 검토 단계를 사람이 한 번 더 보게 남기지 않는다
- 실행 중에는 단계별 체크 목록을 보여 주고, 중간에 실패하면 어디까지 됐는지 그대로 둔다. 닫으면 두께 행이 그 다음 단계를 안내한다(재시도로 중복 생성하지 않는다)

### 2.3 두께 행은 단계 표시 + 다음 행동 버튼 하나

`두께 등록 ✓ · 계산 기준 · 검토 · 게시` 4단계 표시와, 그 단계에 맞는 버튼 하나만 둔다.

| 행 상태 | 버튼 | 동작 |
|---|---|---|
| 게시본 없음, 진행 개정 없음 | `계산 기준 작성` | 마법사를 ②단계부터 연다 |
| 초안 있음 | `검토 요청` / (승인 권한) `검토 요청 후 게시` | 페이지 이동 없이 처리 |
| 검토 중 | (승인 권한) `게시` / 없으면 "승인자의 게시를 기다립니다" | 페이지 이동 없이 처리 |
| 게시본 있음 | 없음 | `계산 기준` 링크로 이력·미리보기·새 개정 |

계산 기준 페이지(`/materials/:id/variants/:vid/rules`)는 그대로 둔다. **최초 등록은 재질 상세에서, 이후 개정 관리는 계산 기준 페이지에서** 한다.

### 2.4 검토 요청이 변경 요약을 채운다

검토 요청은 변경 요약이 있어야 한다(`P2-A04`). 마법사·행 버튼은 요약을 비워 둔 초안에 `최초 계산 기준 등록` 을 실어 보낸다. 서버(`transitionMaterialRule`)는 초안에 요약이 없고 요청에 있으면 그 값을 저장한다. 요약이 이미 있으면 바꾸지 않는다.

### 2.5 잔손질

- `새 재질` 등록 후 알림 없이 `?tab=variants` 로 이동해 두께 항목 탭이 바로 열린다
- 두께 등록·수정·게시 완료는 팝업 대신 목록 위 한 줄 메시지(`role=status`)로 보인다
- 계산 기준 입력 필드는 `rule-fields-form.tsx` 로 빼서 계산 기준 페이지와 마법사가 같은 폼을 쓴다

## 3. 구현

| 층 | 위치 |
|---|---|
| DTO | `MaterialVariantDto.openRule` — 진행 중(초안·검토) 개정 id·상태·lockVersion |
| 서버 | `material-service.ts` 두께 조회가 게시본과 진행 개정을 함께 읽는다. `transitionMaterialRule` 이 `changeSummary` 를 받는다 |
| API | `POST …/rules/:ruleId/transitions` 본문에 `changeSummary` 추가(선택) |
| 화면 | `variant-wizard-dialog.tsx`(마법사), `material-detail-panel.tsx`(단계 표시·다음 행동), `rule-fields-form.tsx`(공용 폼) |

## 4. 검증

- 통합: `material-rule.integration.test.ts` — 요약 없는 초안의 검토 요청 거절 → 요약을 실어 보내면 진행, 재질 상세의 `openRule` 이 초안→검토→게시 뒤 null 로 바뀜
- e2e: `materials.spec.ts` — 새 재질 등록 뒤 두께 탭 자동 진입, 마법사 ①에서 `두께만 등록`, 행의 `계산 기준 작성` 버튼
- 화면(2026-09-13, 로컬 `금속` 재질): 마법사로 `철판 2T` 등록·게시, 기존 `3T` 에 `계산 기준 작성` 으로 ②단계부터 진행·게시. 중간 실패(요약 누락, 수정 전) 후 행의 `검토 요청 후 게시` 로 복구
