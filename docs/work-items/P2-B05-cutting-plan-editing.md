## 1. 목표

`P2-B04` solver 를 사용자 업무로 잇는다. 승인된 수주에서 재단 작업을 만들고, 결과를 원판별로 보고, 필요하면 손으로 고치고, 승인해서 잠근다.

여기부터 재단이 화면에 나온다. `P2-B03`·`P2-B04` 는 계약과 알고리즘만 만들었고 사용자 진입점이 없다.

## 4. 사용자 결정이 필요한 항목

### `D2-B05-I` 재단 작업 묶음 단위 — **확정: (가) 수주 1건 안에서 재질별로 나눈다**

원판이 재질·두께에 매여 있어 한 재단 작업에 여러 재질을 섞을 수 없다. 어디까지를 한 작업으로 볼지가 갈린다.

| 안 | 내용 | 결과 특성 |
|---|---|---|
| **(가) 수주 1건 안에서 재질별로 나눈다** (권장) | 수주 하나에 재질이 셋이면 재단 작업도 셋 | 만들기·되돌리기가 단순하고 수주와 1:N 로 붙는다. 수주가 작으면 원판이 헐겁게 남는다 |
| (나) 여러 수주를 묶어 재단한다 | 같은 재질의 여러 수주를 한 판에 모아 자른다 | 수율이 오른다. 대신 수주별 원가 배분과 부분 취소 처리가 함께 따라온다 |

MFC 에는 그룹 재단이 있었다(`P0-02` `F-15`). 다만 (나)는 원가 배분 규칙이 `P2-B06` 재고·원가와 얽히므로, (가)로 먼저 세우고 그룹 재단은 `P2-B06` 이후 별도로 여는 편이 낫다고 본다.

**2026-08-23 사용자가 (가)를 확정했다.** 그룹 재단은 `P2-B06` 이후 별도 작업으로 연다.

### `D2-B05-J` 수동 보정 방식 — **확정: (가) 고정하고 다시 돌린다**

이 작업의 핵심이자 가장 크게 갈리는 지점이다.

| 안 | 내용 | 결과 특성 |
|---|---|---|
| **(가) 고정하고 다시 돌린다** (권장) | 사용자가 부품 몇 개를 원판·위치에 고정하면, 나머지를 solver 가 다시 배치한다 | 결과가 항상 제약을 지킨다. 사람은 "이건 이 판에" 정도만 지시하고 나머지는 맡긴다. 미세한 위치는 못 맞춘다 |
| (나) 원판 간 이동만 허용 | 부품을 다른 원판으로 옮기라고 지시하면 그 원판 안에서 다시 배치한다 | (가)보다 단순하지만 같은 판 안의 순서는 못 바꾼다 |
| (다) 좌표를 직접 끌어 옮긴다 | 배치 그림에서 부품을 드래그해 좌표를 직접 정한다 | 원하는 대로 놓을 수 있다. 대신 직선 관통 제약을 깨기 쉬워 저장이 거부되는 일이 잦아진다 |

(다)는 자유롭지만 guillotine 제약과 kerf 를 사람이 머릿속으로 지켜야 한다. 조금만 옮겨도 `NOT_GUILLOTINE` 으로 막히는 화면은 쓰기 어렵다. (가)는 사람이 아는 것(어느 부품을 같이 잘라야 하는지)만 지시하고 기하는 solver 에 맡긴다.

**다만 현장에서 실제로 손보는 이유가 무엇인지에 달렸다.** "이 부품은 저 판에 같이" 라면 (가)로 충분하고, "여기 이 자리에" 라면 (다)가 필요하다.

**2026-08-23 사용자가 (가)를 확정했다.** 고정은 `{ partId, sheetIndex }` 로 지시하고, solver 는 고정된 부품을 먼저 그 원판에 놓은 뒤 나머지를 채운다. 고정 자체가 불가능하면(그 원판에 자리가 없으면) 저장하지 않고 이유를 보여 준다. 좌표까지 지정해야 할 일이 실제로 생기면 그때 (다)를 다시 연다.

| 안 | 내용 | 결과 특성 |

### 고정을 어떻게 지키는가

`pins` 는 `{ partId, sheetIndex }` 다. solver 는 원판을 열 때마다 **그 번호에 고정된 부품을 먼저 놓고**, 다른 번호에 고정된 부품은 그 장의 후보에서 아예 뺀다. 후보에서 빼지 않으면 자리가 남을 때 solver 가 먼저 집어가 고정이 무의미해진다.

지킬 수 없는 고정은 결과를 억지로 내지 않고 `CuttingPinError` 로 끝낸다. 예를 들어 부품 전부를 둘째 원판에 고정하면 첫 원판이 비게 되므로 실패한다.

### 기준정보 회전 정책 값이 계약과 다르다

`SheetItem.rotationPolicy` 는 `FREE | KEEP_GRAIN` 인데 계약(`D2-B03-E`)은 `FREE | FIXED` 다. `P2-B03` 문서에 "기준정보와 같은 값"이라고 적혀 있으나 실제로는 다르다. 입력 빌더가 옮긴다.

| 기준정보 | 결 축 | 계약 |
|---|---|---|
| `FREE` | 무관 | `FREE` |
| `KEEP_GRAIN` | `NONE` | `FREE` (지킬 결이 없다) |
| `KEEP_GRAIN` | `WIDTH`·`LENGTH` | `FIXED` |

### 큐를 쓰는 통합 테스트는 따로 돌린다

`processNextJob` 은 조직을 가리지 않고 큐에서 다음 작업을 집는다. 큐를 쓰는 파일을 병렬로 돌리면 서로의 작업을 가져간다. `scripts/run-integration-tests.mjs` 가 이 파일들만 `--no-file-parallelism` 으로 따로 돌리고, 테스트도 자기 `jobId` 가 나올 때까지 돌린다.
