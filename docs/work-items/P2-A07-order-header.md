## 1. 목표

거래처에서 시작하는 수주를 조직별 작업번호로 생성·조회·수정·복사·취소하고, 이후 절곡 항목·계산·가격·생산 단계를 담을 안정적인 수주 헤더를 만든다.

```text
수주 생성
→ 거래처·고객 현장·담당자 선택
→ 납기·비고 저장 및 자동 저장
→ 수주 복사 또는 취소
→ P2-A08 절곡 작업 추가
→ P2-A09 계산·가격 snapshot
→ P2-A10 승인·생산 전환
```

## 2. 근거와 범위

- MFC `Work03Dlg.cpp/.h`는 날짜·번호·고객·현장·연락처·납기·비고를 수주 헤더로 관리한다.
- `SellOpenDlg.cpp/.h`는 기간·거래처·현장 기준의 기존 수주 조회를 제공한다.
- 레거시 `sellsum`은 이전 대상이지만, 웹 수주번호·상태·동시 수정 방식은 서버 업무에 맞게 새로 설계한다.
- `Customer`, `CustomerContact`, `CustomerSite`는 조직 경계, 비활성 수명주기, `lockVersion`을 이미 제공한다.

이번 작업에 포함하는 것은 수주 **헤더**뿐이다.

- 포함: 신규·목록·상세, 거래처/현장/담당자 선택, 납기·외부참조번호·비고, 자동 저장, 복사, 취소, 권한·감사·충돌 처리
- 제외: 절곡 행과 템플릿 복사(A08), 계산·가격·VAT 합계(A09), 승인·생산 상태(A10), 고급 검색·이력·생산 요청(A11), 입면도, 재단·출력·기계 통신

## 4. 데이터·API 계약

### 4.1 Prisma 모델

`SalesOrder`와 `SalesOrderNumberCounter`를 추가한다.

| 필드 | 규칙 |
|---|---|
| `id`, `organizationId` | UUID와 조직 경계 |
| `orderNumber`, `sequenceYear` | `SO-YYYY-000001`, 조직·연도별 유일, 생성 후 불변 |
| `status` | A07은 `DRAFT`, `CANCELLED` |
| `customerId`, `customerSiteId`, `customerContactId` | 고객 필수, 나머지는 선택; 모두 동일 조직·거래처 관계 검증 |
| `ownerMembershipId` | 우리 조직 담당자, 선택; membership이 비활성화돼도 과거 참조는 보존 |
| `orderedAt`, `dueDate` | 생성일과 선택 납기일. 날짜는 `@db.Date` |
| `externalReference`, `memo` | 고객 PO 등 외부 참조(선택)와 내부 비고 |
| `cancelledAt`, `cancelledByMembershipId`, `cancellationReason` | 취소 상태에서만 세 필드 모두 필수 |
| `lockVersion`, `createdAt`, `updatedAt` | 낙관적 잠금과 서버 시각 |

- `@@unique([organizationId, orderNumber])`, `@@index([organizationId, status, updatedAt])`, `@@index([organizationId, customerId, updatedAt])`를 둔다.
- 물리 삭제는 금지한다. 참조된 고객·현장·담당자는 `Restrict` 또는 soft-disable로 수주 이력을 보호한다.
- 새 migration은 빈 로컬 PostgreSQL과 기존 migration 적용 DB 모두에서 검증한다.

### 4.2 Route Handler

```text
GET   /api/v1/orders?query=&status=&customerId=&cursor=
POST  /api/v1/orders
GET   /api/v1/orders/:orderId
PATCH /api/v1/orders/:orderId
POST  /api/v1/orders/:orderId/copy
POST  /api/v1/orders/:orderId/cancel
```

- 모든 쓰기는 `Origin` 검증, Zod strict schema, 표준 오류 envelope, request ID, transaction, `expectedLockVersion`을 적용한다.
- `POST /orders`와 `copy`는 카운터 증가·수주 생성·감사 기록을 하나의 transaction으로 처리한다.
- 감사 이벤트는 생성, 수정, 거래처/현장/담당자 변경, 복사, 취소와 취소 사유를 before/after로 기록한다.
- 목록은 A07에서 최근 수정 순, 번호·거래처 검색, DRAFT/CANCELLED 필터만 제공한다. 기간·담당자·고급 검색은 A11에서 확장한다.

## 5. 화면과 예외 흐름

1. 사용자는 왼쪽 `수주·작업` → `수주 목록` → `새 수주`를 선택한다.
2. 거래처를 빠르게 검색해 선택하고, 기본 고객 현장과 생성자 담당자를 확인한다.
3. 납기·외부 참조·비고를 입력하면 자동 저장 상태가 표시된다.
4. 상세의 `복사`는 새 DRAFT를 열고, `취소`는 사유 입력 공통 팝업을 거쳐 읽기 전용 상태로 전환한다.

- 비활성 거래처·현장·연락처는 신규 선택 목록에서 제외한다. 이미 참조한 수주는 조회 가능하며 경고 배지를 표시한다.
- 다른 조직 UUID, 다른 거래처 소속 현장/담당자, 비활성 owner membership은 `400` 또는 `403`으로 거부한다.
- 네트워크 저장 실패는 마지막 성공 저장 시각과 재시도 행동을 표시한다. 데이터가 유실된 것처럼 성공 안내를 표시하지 않는다.
- 390px에서는 목록과 상세를 별도 route로 유지하고, 표는 가로 스크롤 컨테이너 안에만 둔다.
