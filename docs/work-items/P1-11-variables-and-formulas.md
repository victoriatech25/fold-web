## 1. 목표와 범위

레거시 절곡 수식의 업무 의도와 실제 데이터 표본을 참고하되, 브라우저와 서버에서 안전하고 예측 가능하게 실행되는 독립 수식 엔진을 제공한다.

- 문서 변수의 직접값과 계산식
- 구간 길이 수식과 제품 길이 수식
- 변수 의존성 평가와 변수명 변경 시 참조 일괄 변경
- 구문 오류, 미정의 변수, 0 나눗셈, 순환 참조와 범위 오류 표시
- 수식 결과의 절곡 계산·면적·geometry 반영
- 수식 원문, 계산 스냅샷과 문법 버전의 PostgreSQL 저장·복원
- 공통 팝업을 이용한 변수 삭제 확인

입면도, 임의 JavaScript 실행, 함수·조건식·단위 변환, 가격식, 제작용 DXF는 포함하지 않는다. 첫 완료 범위는 한국어 UI다.

## 2. MFC·레거시 근거와 웹 판단

| 근거 | 확인 내용 | 웹 재구현 판단 |
|---|---|---|
| `_common.h`, `Calculating.h` | 연산자 집합 `+-*/()` | v1의 기본 연산자로 채택 |
| `_common.cpp::Gn_Formula_GetVars` | 연산자로 토큰을 나눠 변수 추출 | 정규 lexer와 parser로 교체 |
| `Calculating.cpp::J2CalWithBrace` | 괄호 포함 double 계산 | BigInt 유리수 중간 계산으로 교체 |
| MFC 변수 lookup | 누락 변수를 `0.0`으로 계산 | 오류로 표시하고 0 대입 금지 |
| `foldxy.lengthvari` 표본 | `D-Y-10`, `B-26-(T*2+1)`, `(B-G)/2` | v1 문법으로 그대로 평가 가능 |
| `sellfold.formulaa` 표본 | `W`, `H-D5`, `(W-D1-D2-D3)/2+5` | 제품 길이 수식으로 지원 |

MFC의 조용한 0 대입과 불명확한 오류는 계산 오판을 만들 수 있으므로 계승하지 않는다. MFC 실행 메커니즘이나 소스 이전이 아니라 실제 업무 수식을 독립적으로 다시 구현한다.

## 3. D1-11 구현 기준

| ID | 적용 기준 |
|---|---|
| `D1-11-A` | 문법 버전은 `fold-expression-v1`로 고정 |

| `D1-11-E` | 최대 source 512자, AST 256 node, 중첩 깊이 32 제한 |
| `D1-11-F` | 중간 계산은 정확한 유리수, 결과는 mm 소수 6자리 반올림 |
| `D1-11-G` | 계산 변수는 다른 변수를 참조할 수 있고 순환 참조는 명시적 오류 |
| `D1-11-H` | 구간 결과는 `> 0`, 제품 길이는 `>= 0`이어야 함 |
| `D1-11-I` | 오류 수식은 초안 편집을 위해 직접값/마지막 스냅샷을 유지하되 오류를 숨기지 않음 |
| `D1-11-J` | 변수명 변경 시 구간·제품·계산 변수의 식별자를 token 단위로 함께 변경 |
| `D1-11-K` | 서버 문서는 원문, 문법 버전과 계산 스냅샷을 보존하며 PostgreSQL JSONB로 왕복 |
| `D1-11-L` | 정상·오류·의존성·DB 왕복·화면 계산 회귀를 종료 게이트로 사용 |

기준은 P1-05·06·09·10의 승인 내용과 “웹 환경에 맞춘 독립 재구현” 원칙을 구체화한 것이다. 사용자 화면 검수 결과에 따라 문구·입력 흐름은 조정할 수 있다.

## 4. 구현 구조

| 위치 | 역할 |
|---|---|
| `src/domain/fold-expression.ts` | tokenizer, parser, AST 평가, 의존성·순환·범위 검증 |
| `src/domain/fold-profile.ts` | 변수와 구간·제품 수식 편집 모델 |
| `src/domain/fold-calculation.ts` | 평가된 길이를 절곡·제품 계산에 적용 |
| `src/stores/fold-editor-store.ts` | 변수 CRUD, 참조 이름 변경, geometry 재생성, Undo/Redo |
| `src/components/canvas-workspace.tsx` | 변수·수식 탭, 직접값/계산식, 결과·오류 표시 |
| `src/domain/fold-document/schema.ts` | 변수 expression을 포함한 strict 서버 문서 계약 |
| `src/domain/fold-document/adapter.ts` | profile ↔ 서버 문서 수식·스냅샷 왕복 |
| `src/server/fold-document/*` | JSONB 저장, canonical checksum과 복원 검증 |

평가 순서는 `직접 변수 → 계산 변수 의존성 → 구간/제품 수식 → 절곡·면적 계산 → 화면 geometry`다. 수식은 `eval`이나 동적 코드를 사용하지 않는다.

## 5. 오류와 편집 정책

| 오류 | 화면 동작 |
|---|---|
| 잘못된 변수명·중복 | 해당 변수 카드에 오류 표시 |
| 문법 오류 | 위치 또는 필요한 토큰을 한국어로 표시 |
| 미정의 변수 | 누락 변수명을 표시하고 0으로 바꾸지 않음 |
| 0 나눗셈 | `0으로 나눌 수 없습니다.` 표시 |
| 순환 참조 | 순환 경로를 `A → B → A` 형태로 표시 |
| 범위·길이 오류 | 구간은 양수, 제품은 0 이상 기준 안내 |

오류가 생겨도 수식 원문은 지우지 않는다. 편집 중 화면이 무너지는 것을 막기 위해 마지막 직접 입력값/스냅샷으로 계산 화면을 유지하고, `수식 오류 n건` 상태를 함께 표시한다. 변수 삭제는 시스템 confirm이 아니라 공통 확인 팝업을 사용한다.

## 6. 저장 계약

- `variables[]`: `name`, 계산 스냅샷 `valueMm`, 선택 `expression`
- `productExpression`: `enabled`, `grammarVersion`, `source`
- `segments[].lengthExpression`: `grammarVersion`, `source`
- 현재 grammar 원문은 `fold-expression-v1`; 과거 브라우저 문법 key는 읽기 호환만 제공한다.
- DB schema를 수식별 컬럼으로 늘리지 않고 `FoldRevision.document` JSONB 안의 버전 문서로 저장한다.
- 체크섬은 수식 원문과 계산 스냅샷을 포함하므로 저장 후 변조나 손실을 탐지한다.

## 8. 사용자 화면 테스트 가이드

### 8.1 준비

1. 프로젝트 루트에서 `npm run dev`를 실행한다.
2. 브라우저에서 Origin 설정과 같은 `http://localhost:3000`을 연다.
3. [로컬 화면 테스트 계정](../local-screen-test-account.md)의 고정 계정으로 로그인한다.
4. 첫 검수는 `저장되지 않은 예제`에서 진행한다. 서버 저장 검수는 새 초안을 만들어 진행한다.

### TC-P1-11-01 직접 변수와 구간 수식

1. `변수·수식` 탭에서 `변수 추가`를 두 번 누른다.
2. 첫 변수를 `W=120`, 둘째 변수를 `D1=20`으로 입력한다.
3. `선 속성`으로 돌아가 선 1의 `수식 입력`을 선택한다.
4. `(W-D1)/2`를 입력한다.
5. `계산 길이: 50 mm`, `최종 전개 폭 180 mm`인지 확인한다.

### TC-P1-11-02 제품 길이 수식

1. `변수·수식` 탭에서 `제품 길이 수식 사용`을 켠다.
2. 제품 길이 수식에 `W*10`을 입력한다.
3. `계산 제품 길이 1200 mm`, 하단 제품 길이 `1200 mm`를 확인한다.
4. 예제 전개 폭 180 mm 기준 제품 1개 면적이 `0.2160 m²`인지 확인한다.

### TC-P1-11-03 계산 변수와 이름 변경

1. 변수를 하나 더 추가해 이름을 `HALF`로 바꾼다.
2. `계산식`을 선택하고 `W/2`를 입력해 계산값 `60 mm`를 확인한다.
3. 선 1 수식을 `HALF-D1/2`로 바꿔 계산 길이 `50 mm`를 확인한다.
4. 변수 `W`의 이름을 `WIDTH`로 바꾼 뒤 HALF 수식이 `WIDTH/2`로 함께 바뀌는지 확인한다.

### TC-P1-11-04 오류 안내와 복구

1. 선 1 수식에 `W/0`을 입력해 `0으로 나눌 수 없습니다.`가 표시되는지 확인한다.
2. `UNKNOWN+1`을 입력해 `UNKNOWN 변수값이 없습니다.`가 표시되는지 확인한다.
3. 변수 A와 B를 만든 뒤 각각 `B+1`, `A+1` 계산식으로 설정해 순환 참조 오류를 확인한다.
4. 오류가 있어도 입력한 수식이 사라지지 않고 화면에는 마지막 직접 길이가 유지되는지 확인한다.
5. 정상 수식 `(WIDTH-D1)/2`로 복구하면 오류가 사라지고 결과가 즉시 갱신되는지 확인한다.

### TC-P1-11-05 공통 삭제 팝업

1. 참조 중인 변수의 `삭제`를 누른다.
2. 브라우저 시스템 confirm이 아니라 제목 `변수 삭제`인 공통 팝업이 나타나는지 확인한다.
3. `취소`는 값을 유지하고 `삭제`는 변수를 제거하며 참조 수식에 오류를 표시하는지 확인한다.

### TC-P1-11-06 PostgreSQL 저장·재열기

1. `새 초안`을 만들고 위의 W, D1, HALF, 구간 수식과 제품 수식을 다시 입력한다.
2. 상단 상태가 `저장됨`이 될 때까지 기다린다.
3. 페이지를 새로고침하거나 `최근 초안`에서 다시 연다.
4. 변수명·직접값·계산식·구간 수식·제품 수식 사용 상태와 계산 결과가 모두 유지되는지 확인한다.
