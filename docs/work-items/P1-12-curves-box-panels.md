## 1. 목표

직선만 가능한 현재 웹 편집기를 원호까지 확장하고, 박스 두 단면의 교차 직선을 바닥 가로·세로로 자동 판정하며, MFC의 패널 업무를 웹에 맞는 독립 도메인으로 재구현한다.

P1-12 완료 시 다음 흐름이 PostgreSQL 저장·복원까지 연결돼야 한다.

```text
직선 작성 → 원호 전환·편집 → 호 길이 계산
박스 두 단면 작성 → 교차 직선 자동 바닥 판정 → 전개도·3D 계산
주 단면 작성 → 패널 연결·방향·계산 역할 지정 → 결과 확인
→ 자동 저장 → 새로고침 복원 → 템플릿 개정
```

입면도, 자유곡선·스플라인, 판금 전개용 정밀 곡면 보정, 제작 DXF, 기계 연동은 포함하지 않는다. 패널의 제작 geometry·3D 안정화는 P1-14·15에서 이어서 검증한다.

## 2. 조사 결과와 웹 재구현 판단

### 2.1 곡선

| 근거 | 확인 내용 | 웹 판단 |

| MFC `Drawx.cpp::Gn_Arc_GetLength_byDepth` | 반원 초과 시 전체 원주에서 작은 호를 빼며, 깊이 1 mm 미만은 직선 길이로 강제 | 큰 호는 지원하되 1 mm 미만 직선 강제는 제거하고 실제 호 길이 계산 |

| 서버 문서 v1 | `geometry.kind=arc`, `side`, `sagittaMm` 이미 예약 | 브라우저 모델과 adapter가 현재 차단한 기능을 활성화 |

원호의 중심각은 `θ = 4 × atan(2s/c)`로 계산한다. `s>0`, `c>0`이면 `0<θ<360°`이며 반원과 큰 호도 같은 식으로 처리된다. 반지름·중심각·호 길이는 파생값이고 저장 원본으로 사용하지 않는다.

### 2.2 박스

현재 웹은 독립된 두 단면을 작성·계산하고 전개도·3D까지 표시한다. `findBoxBaseSegments()`는 두 단면에서 서로 교차하는 직선 쌍을 찾고 합산 길이가 가장 긴 쌍을 바닥 가로·세로로 판정한다. 교차 쌍이 없을 때 임의의 최장선을 대체 사용하지 않는다.

MFC가 `AT_END` sentinel과 변수 `E` 존재 여부로 폭·높이 구간을 전환하는 방식은 계승하지 않는다. 바닥 정보는 도면의 교차 기하에서 파생하며 별도 기준선 ID를 신규 저장하지 않는다.

### 2.3 패널

MFC는 별도 패널 창에서 단면 전체를 복사한 뒤 주 단면 선 번호와 `ref_num`으로 연결한다. 연결 방향은 복사된 단면의 시계·반시계 방향에서 파생하고, 계산에서는 연결된 패널 행 중 최대 `lengthh`를 두 번째 제품 길이로 덮어쓴다. 여러 참조가 있으면 마지막 참조가 결과를 덮을 수 있어 실행 순서 의존성이 있다.

제공된 레거시 PostgreSQL의 `foldxy`, `sellfoldxy`, `foldd`, `sellfold`에는 `ref_num` 또는 패널 컬럼이 존재하지 않았다. 따라서 패널은 DB 결과를 정답으로 간주하지 않고 다음 원칙으로 재구현한다.

- 주 단면과 연결 패널을 별도 객체로 저장한다.
- 배열 순서나 마지막 참조가 결과를 덮지 않게 연결 대상과 계산 역할을 명시한다.
- 재사용 템플릿을 연결할 때는 특정 개정의 snapshot을 문서에 포함해 원본 템플릿 변경의 영향을 받지 않게 한다.
- 패널 계산은 MFC 소스에서 확인한 최대 현 길이를 1차 호환값으로 제공하되, 사용자가 대표 형상을 직접 검증하기 전 게시·제작 출력을 허용하지 않는다.

## 5. 데이터 구조 초안

승인 후 실제 명칭은 schema 구현과 함께 확정하되 관계는 다음을 유지한다.

```text
FoldDocumentV2
├─ documentType: normal | box | panel
├─ primaryBlocks[]
├─ boxDefinition? (과거 문서 읽기 호환 전용)
│  ├─ widthBaseSegmentId
│  └─ depthBaseSegmentId
└─ panelAttachments[]
   ├─ id, name
   ├─ hostBlockId, hostSegmentId
   ├─ direction: clockwise | counterclockwise
   ├─ dimensionRole: none | secondary-product-dimension
   ├─ sourceRevisionId?, sourceChecksum?
   └─ panelBlock snapshot
```

패널 snapshot의 segment ID는 주 단면을 포함한 문서 전체에서 중복되지 않아야 한다. host 선이 삭제되면 validation error를 제공한다. 박스 바닥 교차 쌍이 사라지면 임의의 선을 대체 선택하지 않고 도면 교차 상태 수정을 안내한다.

## 6. 계산·오류 기준

### 6.1 원호

- 현 길이 `c`: `nominalLengthMm`; 좌표 현과 다르면 기존 계약대로 warning을 표시한다.
- 곡 깊이 `s`: `sagittaMm > 0`.
- 반지름: `r = c²/(8s) + s/2`.
- 중심각: `θ = 4×atan(2s/c)`.
- 호 길이: `L = r×θ`이며 `θ`는 radian으로 계산한다.
- `left/right`는 segment 시작→끝의 진행 방향을 기준으로 정의한다. segment 방향을 뒤집는 명령은 화면상의 원호를 유지하도록 side도 함께 반전한다.
- NaN, 무한대, 0 현, 계산 범위 초과는 저장·게시를 차단한다.

### 6.2 박스

- 두 단면에서 서로 교차하는 직선 쌍이 있어야 바닥 폭·깊이를 계산한다.
- 자동 판정 직선의 명목 길이를 `finishedBase`로 사용하고, 전개 바닥에는 연신 보정 결과를 사용한다.
- 바닥 직선 junction과 양쪽 계산 제외는 P1-10 승인 규칙을 그대로 사용한다.
- 박스 3D·전개·제작 geometry는 제품 길이 입력을 요구하지 않는다.

### 6.3 패널

- 같은 host segment에는 1차 범위에서 하나의 패널만 연결한다.
- 여러 host에 패널을 연결할 수 있으나 `secondary-product-dimension` 역할은 문서당 하나만 허용한다.
- `panelSpanMm`은 패널 segment의 명목 현 길이 중 최댓값으로 계산한다. 원호도 호 길이가 아니라 현 길이를 사용해 MFC `GetPanelLength()`의 확인된 의미를 보존한다.
- 역할이 없는 패널은 형상·표시·후속 제작 입력으로만 존재하며 제품 치수를 바꾸지 않는다.
- 패널 template 원본이 개정돼도 기존 연결 snapshot은 자동 변경하지 않는다. 사용자가 명시적으로 교체해야 한다.

- 패널: 연결·분리, 시계·반시계, 다중 host, 단일 dimension role, snapshot 불변, 고아 참조

- UI: 공통 팝업, Undo/Redo, 자동 저장, 읽기 전용 게시 revision, 390~1920 px 반응형 화면
- 회귀: 기존 직선·일반·박스·변수·연신 단위 및 통합 시험 전부 유지

### 7.2 사용자 화면 검수 — 1차 체크포인트

접속 주소는 `http://localhost:3000`이며 `127.0.0.1`로 접속하지 않는다. 로컬 고정 계정은 [로컬 화면 테스트 계정](../local-screen-test-account.md)을 따른다. 데스크톱 기준 Chrome 또는 Edge에서 다음 순서로 검수한다.

#### TC-12-01 원호 표시·계산·직접 편집

1. 로그인 직후 `저장되지 않은 예제`의 첫 선을 선택하고 `선 속성 → 원호`를 누른다.
2. 현 길이가 100 mm인 상태에서 `곡 깊이`를 50 mm로 입력한다.
3. 현 길이 `100 mm`, 호 길이 `157.079633 mm`와 반원 형상이 표시되는지 확인한다.
4. `진행 방향 왼쪽/오른쪽`을 바꾸고 원호가 현의 반대편으로 이동하는지 확인한다.
5. 캔버스 원호 중앙 핸들을 현에서 더 멀리 드래그해 180° 초과 큰 호가 끊기지 않는지 확인한다.
6. `실행 취소/다시 실행`으로 곡 깊이와 방향이 함께 복원되는지 확인한다.

#### TC-12-02 공통 팝업과 직선 복귀

1. 원호가 선택된 상태에서 `직선`을 누른다.
2. 브라우저 기본 confirm이 아닌 `원호를 직선으로 전환` 공통 팝업이 나타나는지 확인한다.
3. 먼저 취소해 원호가 유지되는지 확인한 뒤 다시 열어 `직선으로 전환`을 누른다.
4. 곡 깊이 입력과 원호 핸들이 사라지고 현을 잇는 직선이 되는지 확인한다.

#### TC-12-03 내장 패널과 제품 두 번째 치수

1. 선을 선택하고 `패널 연결`을 누른다.
2. 패널 이름을 구분 가능한 값으로 바꾸고 `패널 최대 현 길이`에 `320`을 입력한다.
3. 연결 방향을 시계/반시계로 변경하고 `계산 역할`을 `제품 두 번째 치수`로 지정한다.
4. 상단 제품 크기 계산 영역에 `패널 두 번째 치수 320 mm`가 즉시 표시되는지 확인한다.
5. `연결 제거`를 눌러 공통 확인 팝업에서 취소와 제거가 각각 동작하는지 확인한다.

#### TC-12-04 박스 교차 직선 자동 판정

1. `박스`를 선택하고 수동 `기준선 지정` 버튼이 없는지 확인한다.
2. 면 1에 바닥 가로 직선을 작성한다.
3. `두 번째 시작점`을 누른 뒤 면 1의 바닥선과 교차하는 바닥 세로 직선을 작성한다.
4. 안내가 사라지고 바닥 크기가 표시되며 `전개도`와 `3D`가 자동 판정한 폭·깊이를 사용하는지 확인한다.
5. 제품 길이를 0으로 두어도 박스 3D와 전개도가 유지되는지 확인한다.
6. 교차가 사라지도록 선을 이동하면 임의의 최장선을 쓰지 않고 교차 직선 안내가 다시 나타나는지 확인한다.

#### TC-12-05 PostgreSQL 저장·복원

1. `새 초안`으로 일반 도면을 만들고 그리기 도구로 선 하나를 작성한다.
2. 해당 선을 원호로 바꾸고 패널을 연결해 두 번째 치수 역할을 지정한다.
3. `지금 저장` 후 상태가 저장 완료로 바뀌는지 확인하고 브라우저를 새로고침한다.
4. 원호의 좌우·곡 깊이, 패널 이름·방향·현 길이·계산 역할이 모두 복원되는지 확인한다.
5. `최근 초안`에서 다른 초안을 열었다가 다시 돌아와도 같은 값이 유지되는지 확인한다.

검수에서 원호 방향·큰 호 형상, 박스 교차 직선 판정 또는 패널 두 번째 치수가 실제 업무와 다르면 사례의 입력값과 기대 결과를 기록한다.

## 8. 완료 기준과 다음 단계
