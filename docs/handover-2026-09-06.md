## 4. 운영 배포 — 발견하고 고친 결함 6건

`v0.1.5`부터 `v0.1.11`까지 태그를 거듭 올리며 하나씩 걷어냈다. 전부 이번 브랜치의 기능 코드가 아니라 **배포 인프라 자체의 결함**이다.

| # | 증상 | 원인 | 조치 | 커밋 |
|---|---|---|---|---|
| 1 | CI가 storage 통합 테스트에서 항상 실패 | GitHub Actions에 MinIO 서비스가 없었음 (`RUN_STORAGE_INTEGRATION` 기본값이 `1`이라 항상 시도됨) | `docker run`으로 MinIO를 띄우고 health 엔드포인트로 대기하는 스텝 추가 | `9f7efe2` |
| 2 | `npm audit` 게이트가 처음으로 끝까지 돌자 실패 | `next`·`prisma` 메이저 업그레이드가 필요한 기존 취약점 14건(9 high) — 이 게이트가 실제로 끝까지 실행된 적이 없어서 지금까지 몰랐음 | **이번 배포 한 번만** 경고로 낮춤. 실제 업그레이드는 별도 작업, 끝나면 되돌려야 함 | `a05094e` |
| 3 | worker가 뜨자마자 재시작 반복 | `app`·`worker` 컨테이너에 `DATABASE_URL`·`APP_ORIGIN`·`AUTH_RATE_LIMIT_SECRET`이 전달되지 않음 (`environment:`에 `NODE_ENV` 뿐이었음) | compose에 세 값을 `${VAR:?...}` 필수로 추가 | `58fedc0` |
| 4 | `.env`에 넣은 값이 다음 배포에서 사라짐 | `deploy.sh`가 배포 때마다 `.env` 파일 전체를 `APP_IMAGE=...` 한 줄로 새로 씀 | `APP_IMAGE` 줄만 `sed`로 갈아 끼우도록 수정. 롤백 경로도 동일하게 수정 | `1dd31fe` |
| 5 | worker가 `Can't reach database server at 127.0.0.1:5432` | 이 서버는 PostgreSQL이 호스트 자신에 떠 있는데, 컨테이너 기본 브리지 네트워크에서 `127.0.0.1`은 컨테이너 자신을 가리킴 | `extra_hosts: host.docker.internal:host-gateway` 추가. `DATABASE_URL` 호스트를 `host.docker.internal`로 변경 | `80e5f90` |
| 6 | worker가 계속 `Restarting` | 같은 이미지의 `HEALTHCHECK`가 `/api/health`(포트 3000)를 확인하는데 worker는 HTTP 서버를 안 띄워 항상 실패 | worker 서비스에 `healthcheck: disable: true` | `7e6d474` |

5번을 고치는 과정에서 **ufw 방화벽**도 막혀 있었다 — 기본 deny에 특정 외부 IP만 5432를 화이트리스트로 열어 뒀고, 도커 브리지 대역(`172.18.0.0/16`, compose가 만든 `fold-web_default` 네트워크)은 목록에 없었다. `sudo ufw allow from 172.18.0.0/16 to any port 5432 proto tcp`로 열었다(사용자가 직접 실행).

## 5. 서버에서 함께 정리한 것

배포 도중 운영 서버(`fold.victoria-tech.com`, self-hosted GitHub Actions 러너 겸용)의 루트 디스크(`/dev/vda2`, 9.8G)가 두 번 완전히 찼다.

- **Docker 데이터 루트를 `/var/lib/docker`에서 `/data/docker`(49G 여유 디스크, `/dev/vdb`)로 이전.** `daemon.json`에 `data-root` 지정
- `actions-runner`의 설치용 tarball(216M)과 자동 업데이트가 남긴 이전 버전 디렉터리(365M), 오래된 `_work`(311M) 정리
- 이 두 가지로도 부족해 배포 중 한 번 더 막혔다 — `deploy.sh`가 `.env`를 지우는 버그(4번)를 고치는 사이 이미지 pull이 반복되며 다시 꽉 참. 최종적으로는 여유가 생겼지만 **근본적으로 이 서버는 루트 파티션이 너무 작다**(`/var/log` 365M, 러너 자체 686M이 상시 부담)

DB 쪽에서는 처음으로 실제 마이그레이션을 적용했다 — 운영 DB(`fold`)가 완전히 비어 있어서 23개 마이그레이션이 전부 새로 적용됐고, 기준정보 시드(`npm run db:seed`)와 관리자 계정(`admin@fold.victoria-tech.com`, `bootstrap-admin.ts`)도 이번에 처음 만들었다.
