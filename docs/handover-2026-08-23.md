### 2.3 표본 실행 결과 — 이 수치가 기준선이다

레거시에 재단 결과가 없어 비교 대상이 없다(`D2-B03-Q`). **웹에서 나온 아래 수치가 앞으로의 기준선이다.**

| 표본 | 원판 수 | 수율 | 미배치 | 위반 | 소요 |
|---|---|---|---|---|---|
| 표본 1 (E.G.I-1.6T) | 5 | 78.51% | 0 | 0 | 4ms |
| 표본 2 (H/L-1.2T) | 1 | 83.48% | 0 | 0 | 4ms |
| 표본 3 (철판-1.6T) | 5 | 90.6% | 0 | 0 | 3ms |

### 2.4 기록해 둘 것 셋

1. **목적함수에 미배치 수량을 맨 앞에 보탰다.** `D2-B03-O` 의 우선순위(원판 수 → 수율 → 절단 횟수)는 부품이 모두 배치된 상태를 전제로 한 것이라, 그대로 옮기면 아무것도 안 놓아 원판 수 0인 계획이 최선으로 뽑힌다.
2. **`SheetItem.rotationPolicy` 가 계약과 값이 다르다.** 기준정보는 `FREE | KEEP_GRAIN`, 계약은 `FREE | FIXED` 다. `P2-B03` 의 `D2-B03-E` 가 "기준정보와 같은 값"이라고 적은 것은 사실과 다르다. 입력 빌더가 옮긴다(지킬 결이 없으면 `FREE`).
3. **큐를 쓰는 통합 테스트는 병렬로 돌리면 서로를 문다.** `processNextJob` 이 조직을 가리지 않아 앞 파일이 남긴 작업을 집어 간다. 단독 실행에서는 통과하고 전체 실행에서만 깨져 원인을 찾기 어려웠다. 지금은 그 파일들만 `--no-file-parallelism` 으로 따로 돌린다.

## 5. 다른 장비에서 이어받기

### 5.1 처음 한 번

```bash
git clone git@github.com:victoriatech25/fold-web.git
cd fold-web
git checkout p2-a09-a11-order-calculation-approval-history
npm ci
```

`.env.local` 은 저장소에 없다. 다음 값이 필요하다.

| 변수 | 내용 |
|---|---|
| `DATABASE_URL` | 개발 DB. `postgresql://…@127.0.0.1:5432/fold_web_dev?schema=public` |
| `TEST_DATABASE_URL` | 통합 테스트 DB. `…/fold_web_test?schema=public` |
| `APP_ORIGIN` | `http://localhost:8000` (포트 8000 고정) |
| `STORAGE_*` | MinIO 접속. `compose.yaml` 의 `storage` 서비스 기본값과 맞춘다 |
| `LEGACY_REFERENCE_DATABASE_URL` | 레거시 참조 DB. 읽기 전용 조사용. 문서·코드에 적지 않는다 |

DB 를 세운다.

```bash
npx prisma generate
npm run db:migrate:deploy
npm run db:seed
```

### 5.2 매번

터미널 세 개를 쓴다.

```bash
docker compose up -d storage
```

```bash
npm run dev
```

```bash
npm run worker
```

| 항목 | 값 |
|---|---|
| 웹 | `http://localhost:8000` (`APP_ORIGIN` 과 일치해야 한다) |
| MinIO API·콘솔 | `127.0.0.1:9000` · `http://127.0.0.1:9001` |
| PostgreSQL | Homebrew `postgresql@16`, `127.0.0.1:5432` |
| 로그인 | [로컬 화면 테스트 계정](./local-screen-test-account.md) |

### 5.3 걸리기 쉬운 것

- **worker 는 코드를 바꾸면 반드시 다시 띄운다.** watch 가 없다. 기동 로그의 `types` 에 `cutting.optimize`·`dxf.export`·`storage.cleanup` 이 모두 있어야 한다.
- **`prisma generate` 뒤에도 worker 를 다시 띄운다.** 옛 클라이언트를 물고 있으면 새 컬럼에서 깨진다.
- **스키마를 바꿨으면 `npm run db:migrate:deploy` 로 개발 DB 에도 올린다.** 이번에 실제로 걸렸다(위 3절).
- **e2e 를 돌리기 전에 개발 서버를 내린다.** Next 는 같은 디렉터리에서 두 번째 dev 서버를 거부한다.
- **테스트 DB 초기화는 Prisma 가 AI 실행을 막는다.** 사용자 동의를 받아 `PRISMA_USER_CONSENT_FOR_DANGEROUS_AI_ACTION` 에 동의 문장을 그대로 넣어야 한다.
- **검증 출력의 꼬리만 보지 않는다.** 파일 수·건수를 직접 센다. 새 테스트 파일이 통합 러너 목록에 없어 안 돌던 일이 있었다.
