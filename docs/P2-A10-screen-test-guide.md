## 1. 접속 준비

| 항목 | 값 |
|---|---|
| 로그인 | `http://localhost:3001/login` |
| 이메일 | `screen-test-admin@local.test` |
| 비밀번호 | `Browser verification phrase 2026!` |

검수 전용 새 수주를 하나 만든다. 절곡 작업을 추가하고 `수주 계산`까지 실행한다. 생산 요청 이후에는 상태를 되돌릴 수 없으므로 다른 검수에 사용 중인 수주는 선택하지 않는다.

## 2. 계산 상태 연결

### `A10-STATE-01` 작성 중→계산 완료→작성 중

1. 새 수주의 상단 상태가 `작성 중`인지 확인한다.
2. 절곡 작업을 추가하고 수주를 계산한다.
3. 상단 배지와 `검토·승인·생산 상태`의 현재 단계가 `계산 완료`인지 확인한다.
4. 작업 수량을 변경해 저장한다.

기대 결과: 상태가 다시 `작성 중`이 되고 계산 영역에는 `재계산 필요`가 표시된다. 다시 계산하면 `계산 완료`로 복귀한다.

## 3. 승인과 불변성

### `A10-APPROVE-01` 최신 계산 승인

1. `계산 완료` 상태에서 `수주 승인`을 누른다.
2. 승인 확인 팝업의 설명을 확인하고 승인한다.
3. 완료 팝업을 닫는다.

기대 결과:

- 현재 단계와 상단 배지가 `승인`으로 바뀐다.
- 승인자, 승인 시각, 고정 계산 버전, 결과 checksum 앞 12자가 표시된다.
- 고정 계산 버전과 계산 영역의 최신 버전이 같다.

### `A10-IMMUTABLE-01` 승인 후 변경 차단

승인 상태에서 다음을 확인한다.

- 거래처·담당자·납기·외부 참조·비고가 읽기 전용이다.
- 절곡 작업 추가·입력 저장·복사·정렬·제거 버튼을 사용할 수 없다.
- 계산·재계산 버튼을 사용할 수 없다.
- 화면을 새로고침해도 승인 계산 버전·checksum·금액이 유지된다.

### `A10-UNAPPROVE-01` 승인 취소

1. `승인 취소`를 누른다.
2. 사유를 입력하지 않고 완료할 수 없는지 확인한다.
3. `고객 요청 재검토`를 입력해 승인 취소한다.

기대 결과: 상태가 `계산 완료`로 돌아가고 입력이 다시 활성화된다. 기존 계산 버전과 금액은 유지되며 승인 고정 정보만 해제된다. 입력을 바꾸면 `작성 중/재계산 필요`가 된다.

## 4. 생산 단방향 흐름

### `A10-PRODUCTION-01`

입력을 바꾸었다면 다시 계산·승인한 뒤 아래 주 행동을 순서대로 실행한다.

```text
승인
→ 생산 요청
→ 생산 시작
→ 생산 완료
→ 수주 마감
```

각 단계에서 확인 팝업과 완료 팝업이 나타나고 현재 단계·상단 배지가 함께 변경되어야 한다. `생산 요청` 이후에는 승인 취소 버튼이 없어야 하며 모든 수주 입력과 계산은 계속 읽기 전용이어야 한다. `마감`에는 다음 상태 버튼이 없어야 한다.

## 5. 오류·권한·동시성

### `A10-STALE-01` stale 계산 승인 거부

작업 입력을 변경해 `재계산 필요`로 만든 상태에서는 `수주 승인` 행동이 없어야 한다. API를 직접 호출하더라도 현재 입력과 일치하는 최신 계산이 없으면 `409`로 거부되어야 한다.

### `A10-CONFLICT-01` 두 탭 상태 전이

1. 같은 계산 완료 수주를 두 탭에서 연다.
2. 첫 탭에서 승인한다.
3. 두 번째 탭의 이전 lock으로 승인한다.

기대 결과: 늦은 요청은 충돌 팝업으로 거부되며 상태가 중복 전이되지 않는다. 새로고침하면 첫 탭의 승인 정보가 보인다.

### `A10-PERMISSION-01`

- `order.read`만 있는 사용자는 상태와 승인 정보를 읽지만 전이 버튼이 없어야 한다.
- `order.edit/order.calculate`만 있고 `order.approve`가 없는 사용자는 계산까지 가능하지만 승인할 수 없어야 한다.
- 다른 조직의 수주 UUID는 조회·전이할 수 없어야 한다.

## 6. 감사·반응형

### `A10-AUDIT-01`

`관리 > 감사 로그`에서 `수주 승인·생산 상태 전이`를 확인한다. 전이 행동, 이전·다음 상태, lock, 승인 시 계산 스냅샷 번호가 있어야 하며 전체 계산 JSON이나 작업 문서는 없어야 한다. 승인 취소 이벤트에는 입력한 사유가 있어야 한다.

### `A10-RWD-01`

브라우저 폭 `390px`, `768px`, `1280px`, `1920px`에서 상태 패널을 확인한다.

- 전체 viewport 가로 스크롤이 없어야 한다.
- 승인 정보가 좁은 화면에서 한 열로 자연스럽게 쌓여야 한다.
- 주 행동·승인 취소 버튼과 공통 팝업에 접근할 수 있어야 한다.
- 긴 checksum 때문에 화면 폭이 늘어나지 않아야 한다.
