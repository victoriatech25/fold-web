## 3. 기본 수명주기

### `A07-UI-01` 생성과 자동 저장

1. `업무 > 수주·작업`에서 `수주 목록`을 연다.
2. 활성 거래처를 선택하고 `새 수주`를 누른다.
3. 상세에서 번호가 `SO-YYYY-000001` 형식이고 상태가 `작성 중`인지 확인한다.
4. 거래처를 바꿔 고객 현장·거래처 담당자가 해당 거래처의 기본값으로 바뀌는지 확인한다.
5. 사내 담당자, 납기 `2026-08-31`, 외부 참조 `MANUAL-PO-0815`, 내부 비고 `수동검수 수주`를 입력한다.
6. `변경 내용 저장 대기 중` → `저장 중` → `저장됨` 순서를 확인하고 새로고침한다.

기대 결과:

- 생성자는 기본 사내 담당자로 선택된다.
- 약 1초 뒤 자동 저장되며 새로고침 후 모든 값이 복원된다.
- `저장` 버튼으로 즉시 저장할 수도 있다.
- 수주일과 납기는 날짜로 표시되고 시간 입력은 없다.

### `A07-UI-02` 복사와 취소

1. 작성 중 수주에서 `복사`를 누르고 공통 확인 팝업의 `복사`를 누른다.
2. 새 URL과 새 수주번호가 발급됐는지 확인한다.
3. 거래처·현장·담당자·납기·외부 참조·비고가 복사됐는지 확인한다.
4. 사내 담당자가 복사 실행자로 지정됐는지 확인한다.
5. `취소`를 누르고 사유 `수동 화면 검수 취소`를 입력한다.

기대 결과:

- 원본과 사본 번호는 다르고 원본 번호는 바뀌지 않는다.
- 취소 후 상태가 `취소`, 사유가 화면에 표시된다.
- 모든 입력과 저장·복사·취소 버튼이 비활성화된 읽기 전용 화면이 된다.
- 취소 수주에서 복사하거나 다시 취소할 수 없다.

### `A07-UI-03` 목록 검색

1. `수주 목록`으로 돌아간다.
2. 사본 수주번호로 조회한다.
3. 거래처명 일부로 조회한다.
4. 상태를 `작성 중`, `취소`, `전체 상태`로 바꿔 조회한다.

기대 결과: 최근 수정 순으로 최대 50건이 표시되고 번호·거래처명·상태 조건에 맞는 수주만 보인다.

## 4. 충돌·권한·비활성 검수

### `A07-CONFLICT-01` 두 탭 동시 수정

1. 같은 작성 중 수주 URL을 두 탭에서 연다.
2. 첫 탭에서 비고를 변경하고 `저장됨`을 기다린다.
3. 두 번째 탭에서 다른 비고를 입력해 저장한다.
4. `수주 변경 충돌` 공통 팝업에서 `서버본 불러오기`를 선택한다.
5. 다시 충돌을 만든 뒤 `사본 만들기`를 선택한다.

기대 결과:

- 늦은 저장은 서버본을 덮어쓰지 않고 `409 CONFLICT`로 처리된다.
- 서버본을 선택하면 최신 값과 lockVersion을 읽는다.
- 사본을 선택하면 새 번호에 현재 입력값을 보존한다.

### `A07-PERM-01` 권한

- `order.read`만 있는 사용자는 목록과 상세를 읽을 수 있지만 생성·저장·복사·취소 버튼이 없어야 한다.
- `order.read`가 없는 사용자는 `/orders`와 API에 접근할 수 없어야 한다.
- 다른 조직의 수주 UUID, 현장·담당자 UUID를 요청해도 조회하거나 저장할 수 없어야 한다.

### `A07-INACTIVE-01` 비활성 참조

기존 수주가 참조하는 거래처·현장·담당자를 기준정보에서 비활성화한 뒤 상세를 다시 연다.

기대 결과: 기존 참조 이름과 비활성 경고는 보존되지만 새 선택 목록에는 나타나지 않는다.

## 5. 감사·반응형 검수

### `A07-AUDIT-01` 감사 로그

`관리 > 감사 로그`에서 수주 생성·변경·복사·취소 이벤트를 찾는다. 행위자, 수주 ID, 요청 ID, 변경 전후와 취소 사유가 올바른 이벤트에 기록돼야 한다.

### `A07-RWD-01` 화면 폭

브라우저 폭 `390px`, `768px`, `1280px`, `1920px`에서 목록과 상세를 확인한다.

- 전체 viewport 가로 스크롤이 없어야 한다.
- 필드와 버튼이 읽는 순서대로 쌓여야 한다.
- 공통 팝업의 본문과 하단 버튼에 접근할 수 있어야 한다.
- 모바일 메뉴에서 `수주·작업`을 열고 닫을 수 있어야 한다.
