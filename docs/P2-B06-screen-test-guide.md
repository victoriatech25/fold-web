# P2-B06 원판 사용 실적 화면 테스트 가이드

> 대상: [P2-B06 상세계획](./work-items/P2-B06-sheet-usage-remnant.md)
>
> 작성일: 2026-08-30. 2026-09-06 실제 화면 라벨·경로 기준으로 재작성
>
> 검수자: 사용자 본인
>
> 검수 결과: **여섯 항목 전체 통과 (2026-09-05)**. 검수 중 결함 둘을 찾아 고쳤다 — 승인 취소 뒤 재승인이 항상 500 이던 것, 원판 필터 해제가 주소에 반영되지 않던 것. 화면 개선 셋을 함께 반영했다

재단 결과가 처음으로 재단 밖으로 나오는 단계다. 승인이 곧 "원판을 썼다" 가 된다.

**남은 조각(잔재)은 다루지 않는다.** 현장에서 다시 쓰지 않는다는 것이 확인돼 2026-08-30 `D2-B06-H` 를 (가)로 되돌렸다. 남은 면적은 손실에 들어 있다.

- **수주 상세 `승인·생산` 탭**: 그 수주가 쓴 원판
- **생산·출력 → 원판 사용 실적**: 기간·원판별 집계
- **재단 상세**: 승인 취소
- **기준정보 → 재질·두께 → 원판 품목**: 그 원판만 걸러 보기

자동 검증은 단위 6건과 통합 3건이 돈다. 이 가이드는 자동 검증이 대신할 수 없는 것 — **숫자가 업무 감각에 맞는지** — 를 본다.

## 1. 준비

터미널 셋을 띄운다.

```bash
docker compose up -d storage
```

```bash
npm run dev
```

```bash
npm run worker
```

- 웹은 `http://localhost:8000`. `npm run dev`가 `PORT=8000`을 고정한다
- **`worker`를 띄우지 않으면 재단이 `계산 중`에서 멈춘 채 영원히 끝나지 않는다.** 재단 계산은 큐에 쌓이고 `worker` 프로세스가 꺼내 처리하는 구조라, dev 서버만 켜져 있으면 화면이 "계산 중"만 반복해서 보여준다
- 이번 작업은 스키마를 바꿨다. 화면을 열기 전에 개발 DB 에 마이그레이션이 올라가 있어야 한다

```bash
npm run db:migrate:deploy
```

## 2. 검수 항목

### 2-1. 승인하면 원판 사용 실적이 남는다

1. 왼쪽 메뉴 **영업관리 → 수주 등록/조회**(`/orders`)에서 계산까지 끝난 수주를 하나 연다. 없으면 새 수주를 만들고 절곡 작업을 넣어 계산까지 진행한다
2. 수주 상세의 **`승인·생산`** 탭을 연다
3. 위쪽 **`검토·승인·생산 상태`** 카드에서 **`수주 승인`** 버튼을 누른다. 확인 팝업이 뜨면 승인한다. 승인 후에는 수주 입력·계산을 바꿀 수 없다
4. 같은 탭 아래 **`재단`** 영역에 **`재단 시작`** 버튼이 나타난다. 누르면 재질별로 재단 작업이 하나씩 생긴다
5. **`재단 작업 확인`** 버튼(또는 목록의 재단 링크)을 눌러 재단 상세(`/cutting/{id}`)로 이동한다
6. 상태가 `계산 중`이면 `worker`가 처리할 때까지 기다린다. 화면이 2초마다 자동으로 다시 읽으므로 새로고침은 필요 없다. 오래 걸리면 1절의 worker가 떠 있는지 먼저 확인한다
7. `계산 완료`로 바뀌면 **`승인`** 버튼을 누른다. "개정 N을 승인합니다. 승인하면 잠기고 다시 계산할 수 없습니다." 팝업에서 확인한다
8. 수주 상세 `승인·생산` 탭으로 돌아간다
9. **확인**: `재단` 영역에 `원판 사용 실적` 표가 생기고 총 장수·수율이 보인다
10. **확인**: 표의 장수가 재단 결과의 원판 수와 같다

**여기서 볼 것**: 손실 면적이 업무 감각에 맞는가. trim·자투리와 쓸 만한 크기로 남은 조각이 **모두** 손실에 들어 있다.

### 2-2. 원가와 중량이 붙는다

1. 왼쪽 메뉴 **기준정보 → 재질·두께**(`/materials`)에서 쓰고 있는 재질을 연다
2. **`기본정보`** 탭의 **`밀도(kg/m³)`** 필드에 값을 넣고 저장한다. 밀도가 없으면 중량 칸은 `—`로 나온다
3. **`두께 항목`** 탭에서 쓰고 있는 두께 행의 **`원판 품목`** 버튼을 눌러 원판 품목 화면(`/materials/{materialId}/variants/{variantId}/sheet-items`)으로 이동한다
4. 쓰고 있는 원판 카드의 **`수정`** 버튼(연필 아이콘)을 눌러 편집 팝업을 연다
5. **`중량·구매 참고`** 섹션의 **`표준 구매가 (원, 참고)`** 필드에 값을 넣고 저장한다. 이 항목이 가이드가 말하는 "참고 매입원가"다
6. 새 수주로 2-1 을 다시 한다

- **확인**: 사용 실적에 중량과 참고 매입원가가 채워진다
- **확인**: `표준 구매가`가 비어 있는 원판을 쓴 실적은 원가만 `—`이고 장수·면적은 그대로 나온다

원가는 **판매가가 아니라 참고 매입원가**다(`D2-B06-D`). 수주 금액은 이 값과 무관하게 그대로다(`D2-B06-J`).

### 2-3. 기간별 실적을 본다

1. 왼쪽 메뉴 **생산·출력 → 원판 사용 실적**(`/cutting/usage`)을 연다
2. **확인**: 최근 한 달이 기본으로 조회되고, 위쪽에 총계가, 아래에 원판별 합계와 재단 건별 내역이 나온다
3. 조회조건의 시작일을 미래로 바꿔 다시 조회한다
4. **확인**: "이 기간에 승인된 재단이 없습니다." 안내가 나오고 총계 줄 자체가 사라진다

**여기서 볼 것**: 원판별 합계의 수율이 재단 상세에서 본 수율과 크게 어긋나지 않는가.

### 2-4. 기준정보에서 원판 하나만 걸러 본다

1. **기준정보 → 재질·두께** → 재질 → **`두께 항목`** 탭 → **`원판 품목`**에서 카드 아래쪽의 **`이 원판의 사용 실적 보기`** 링크를 누른다
2. **확인**: `/cutting/usage?sheetItemId={id}`로 이동하며 사용 실적 화면이 그 원판만 걸러 열린다
3. **`원판 필터 해제`**를 누르고 다시 조회한다
4. **확인**: 전체가 다시 보인다. **주소창의 `?sheetItemId=`도 함께 지워졌는지 확인한다** — 남아 있으면 새로고침했을 때 필터가 되살아난다

### 2-5. 승인을 취소하면 실적이 무효가 된다

1. 승인된 재단 상세(`/cutting/{id}`)를 연다
2. **확인**: "OO가 승인했습니다. 승인된 재단은 다시 계산할 수 없습니다." 안내 옆에 **`승인 취소`** 버튼이 있다
3. 누르고 "승인 취소 사유"를 입력한다
4. **확인**: 상태가 `계산 완료`로 돌아가고 `다시 계산` 버튼이 다시 활성화된다
5. 수주 상세로 돌아간다
6. **확인**: 사용 실적 줄이 **지워지지 않고 취소선으로** 남는다. 상태 배지가 `무효`로 바뀌고 취소 사유가 함께 보이며, 총계에서는 빠진다
7. **회귀 확인**: 같은 재단 상세에서 **`승인`**을 다시 누른다. 새 실적이 정상적으로 생성돼야 한다 — 유일 제약을 살아 있는 실적에만 걸도록 좁힌 수정(`20260905030000_sheet_usage_active_unique`)이 들어가기 전에는 여기서 항상 500이 났다

지우지 않고 무효로 남기는 것이 `D2-B06-F` 다. 왜 사라졌는지가 남아야 한다.

### 2-6. 권한

1. **시스템 → 역할과 권한**(`/admin/roles`)에서 테스트용 역할을 만들거나 고른다. 권한 목록에서 **`cutting.optimize`** 하나만 체크하고 저장한다
2. **시스템 → 조직 관리**(`/admin/users`)에서 검수용 계정에 그 역할을 붙인다
3. 그 계정으로 로그인한다
4. **확인**: `생산·절단`, `원판 사용 실적` 화면은 보이고 권한 없는 모듈 탭(영업관리·기준정보·시스템)은 메뉴에서 사라진다
5. **확인**: 재단 상세의 `승인 취소` 버튼이 보이지 않는다
6. **확인**: 화면만 숨기는 게 아니라 `/api/v1/cutting-plans/{planId}/approval/cancel`을 직접 호출해도 `403 FORBIDDEN`이다
7. 확인이 끝나면 **역할·권한을 원상복구한다**
